# 一次真实会话里跑出来的流程（2026-11-17 → 11-18）

> **这一份是观察记录，不是规范。** 规范在 `SKILL.md` 与 `references/`。
> 它的用途：说明 0.8.0 的三份 references 与两个 gate 模式**是从哪条真实故障长出来的**。
>
> 样本：`session-3be1c48a`，DSJY 高阶超图记忆库 0.0.3。
> 体量：71 轮、160 条用户消息（其中真指令约 60 条）、1,026 次工具调用（`pwsh` 652 · `write` 95 · `edit` 90 · `subagent` 31 · `team_task_create` 30）。

## 1 实际发生的六个阶段

| 段 | 用户要什么 | 实际做了什么 | 收口靠什么 |
|---|---|---|---|
| **P0 对矛盾** | 「找三维节点的描述文档」「这三个基本正确，要综合重新来看」「再看看还有没有矛盾的说法，全部看一遍」×5 | 全仓扫 md，逐条比「维 / 跳 / 源头」的说法 | **没用**：口径写在回答里，下一轮又变 |
| **P1 认知重建** | 「回到原来的立项即标准，把记忆系统的哲学全部摘出来」 | 交分析稿 → 被驳回「不要写这种东西，有个屁用」 | 用户自己写条文，AI 只许「对齐 / 补充 / 指出矛盾」 |
| **P2 范畴与立项** | 「要先明确范畴，包括数学范畴，工程范畴」「要写立项书作为总索引总揽」 | 九域目录、范畴表、文档纪律、Rust/TS 选型判据 | 立项书七段 + 文档宪法 + 前缀表 |
| **P3 形式化** | 「先把形式化证明做一下……你写好方式，开始让子代理逐条去证明」 | 4 个子代理并行写 Lean 文件 | 每个子代理交「编译退出码 + sorry 计数 + 定理数」 |
| **P4 工程切片** | 「先开发一个功能，逐个功能来实现」（同一段话重复 12 次） | F1–F8 八片，每片 core + api 两个子代理 | 语义编号 + 测试 + 反证 + 开发日志 |
| **P5 重构** | 「按原本的依赖流程，逐个展开（递归进去规划设计）去做重构」 | R1–R6：区间语义归一、投影归一、删壳、文档对账、拆模块 | `cargo test --workspace` 条数不变 + 对账脚本退出码 0 |

**P0 是唯一一段跑了两小时还在原地的一步。** 它不是「做得不好」，是**没有产物可以收口**：
矛盾只存在于回答里，下一轮重新讨论就又活了。

## 2 六条流程事实（每条都能对上原文）

### 2.1 用户的指令是「形态 + 判据」，不是「任务」

```
不要写这种东西，有个屁用。
记忆库系统：
1.此系统由高阶超图驱动。这个系统必须是超图。
…
7.{} 内有序，顺序即时间。[] 是节点，{} 是超边；超边可作成员进入另一个超边，所以超边=节点。
```

用户自己给的是**编号条文**；AI 交的是**分节分析稿**。被驳回的不是内容，是形态。

⇒ 落到 `r5-axiom-chain.md` §5 Q4：**用户说「不要写这种东西」= 形态被驳回，改形态，不加解释。**

### 2.2 认知是靠「指回上一条」验的，不是靠「听起来对」

```
AI（早期）：要做去重。
用户：去重是错误描述，是因为（超边=节点）。已有节点的情况下，只建超边集。
      不需要去重……没有这层认知，皆是做出来的又是四不像的东西。
```

用户给的判据是**可推导性**：这条工程规则，能不能从上一条条文推出来。

⇒ 落到 `r5-axiom-chain.md` §3：锚 → 拆 → 推 → 落，四步。落到 C10。

### 2.3 矛盾必须逐行裁决，不许「综合」

```
你不要去对代码，对旧的，和新的设计稿，总稿 总稿，立项书等等。去看。
是不是这么一回事。以我当前的话为基准，将矛盾的原话全部拉出来逐行比对。
```

「综合」在用户的语汇里是**和稀泥**：两句话都留着，各自都「对」，于是下游永远两套说法。

⇒ 落到 `r5-axiom-chain.md` §5 Q3：拉出全部原话，逐行裁决，写明哪一句作废。

### 2.4 立项书是「能被逐行比对的那一份」

```
回到原来的立项即标准。
```

这句话在会话里被用来**判下游文档**：每篇文档都要能被立项书判「是 / 否」。
写成「项目介绍」的立项书判不了任何东西 —— 于是有了：

```
讨论 → 写文档 → 再讨论 → 又写一篇 → 两篇说法不同 → 谁对？
```

⇒ 落到 `r6-project-charter.md` 全文：七段 + 九域 + 宪法 + 状态表。

### 2.5 派活靠九段任务书，不靠「你去做 F2」

真实任务书（`team_task_create`，30 份，形态高度一致）：

```
## 环境            根 / 命令 / 工具链钉在哪
## 写域            只许改这些 / 不许改（含「不许碰别的 crate」）
## 已冻结契约       签名、字段顺序、常量，原样贴出
## 语义（A1…A12）   每条一句，可判
## 测试            一编号一个测试，不许 #[ignore]
## 反证            注入 a/b/c 分别必须红 → 还原 → 全绿
## 禁止            todo!/unimplemented!/硬编码/吞错误
## 交付            末 20 行 + 实现位置 + 红点 + 实际 JSON
write_scopes / blocked_by
```

**每一次成功，都是因为这九段齐；每一次返工，都能指出缺了哪一段。**

⇒ 落到 `r7-slice-board.md` §3 与 `templates/任务书.md`。

### 2.6 验收不靠报告，靠「反证 + 独立探针 + 对账脚本」

会话里出现过三次「全绿但不对」：

| 症状 | 真相 |
|---|---|
| 子代理报 `0 处要改` | 它把 12 条语义写成测试压上去，全绿 —— 这**是**有效结论，因为它同时报告了注入三处都红 |
| 报 `272 passed`，实际基线 `276` | 差 4 条是 lead 自己建的验收探针；对上了才发现是口径差 |
| 文档说 77 个 pub，代码 104 个 | 靠人读判断不了，靠 `doc-reconcile.py` 双向比，退出码 0 才算对齐 |

⇒ 落到 `r7-slice-board.md` §4（lead 三件事）与 §6（对账）、G8（没有反证的判据不算判据）。

## 3 用户重复最多次的一段话（值得单列）

同一段指令，在 P4/P5 里出现 **12 次**，一字不差：

```
要根据架构，先开发一个功能，逐个功能来实现，你来负责规划本次任务，明确要实现什么，
怎么连接，怎么写架构 文件夹位置，查验规范标准，而不是用cli测试所谓的通过算通过，
而是代码和功能必须要通过，数据流和信息流要看。因此你要从实现目标开始明确，
数据流和信息流怎么走，这个流程要如何在工程上被程序执行，这个任务再分发给子智能体，
最后由你明确它们的任务的同时，验收它们的任务，检查是否与语义属实，而不是套壳或者查表，
再或者瞎搞瞎写的代码。完成后继续写一份开发日志。
```

**这段话是用户手写的「切片协议」**，七件事：

```
1 依架构      2 一次一片     3 lead 规划     4 数据流 + 信息流都要看
5 不信 cli 绿  6 派给子代理并验收语义属实（防套壳 / 查表 / 瞎写）  7 开发日志
```

**它被重复 12 次，是因为 AI 每次都会漏掉其中一两件。** 这正是 0.8.0 把 `r7-slice-board.md`
写成「四问 + 九段 + 三件事」的原因：**用户不得不手打的东西，应该变成 skill 的默认产出。**

## 4 这段流程暴露的三个缺陷（对应本次改动）

| 缺陷 | 会话里的证据 | 0.8.0 的修法 |
|---|---|---|
| **认知：抄结论不抄前提** | 「没有这层认知，皆是四不像」 | `r5-axiom-chain.md` + C10/C11 |
| **立项：文档各自解释** | 「各自解释的情况，而不是互相解释」 | `r6-project-charter.md` + 宪法 D1–D6 + `--charter` |
| **交付：绿 ≠ 完成** | 「而不是用 cli 测试所谓的通过算通过」 | `r7-slice-board.md` + 任务书九段 + G8 + `--board` |

## 5 还可以再补的三处（0.8.1 候选）

**按会话里实际浪费掉的时间排序**：

1. **P0 没有产物**。「再看看还有没有矛盾的说法，全部扫一遍」跑了 5 遍。
   缺一份 `矛盾裁决表.md`（原话 A / 原话 B / 出处 / 哪句作废 / 依据哪条公理 / 下游要改哪几处），
   以及一个 `--conflicts` 模式：扫描 docs 里同一概念的多种说法，要求每个冲突都有裁决行。
2. **子代理失败没有兜底**。会话里 `agent-1`–`agent-4` 四个后台子代理**全部失败且没留下任何收尾消息**。
   缺一条纪律：派活前先跑一个最小探针（能编译 / 能读文件 / 能写文件），失败要么重派要么降级为 lead 自己写。
3. **模型切换导致口径漂移**。会话中模型被换了 3 次，每次切换后都要重新对齐条文。
   缺一条：切换后第一件事是重读「唯一权威表」，不是继续干活。

## 6 一句话

> **用户不是没讲清，是他讲清的那一版被反复转述成了另一版。**
> **skill 要做的不是让他再讲一遍，是让转述无处发生：原话入账、公理成链、概念一处、判据能红。**
