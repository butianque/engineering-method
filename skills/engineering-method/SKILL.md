# 工程方法论（分发层）

> **本文件只做三件事**：给一条主干、给一组闸门、给一张「谁说了算」的表。
> 细节全在 `references/`，按需读，不要全读。
>
> **本 skill 自己也受它自己那套规则约束**：一个概念只许一处定义（C12）。

---

## 核心（一句话）

> **拿到一个请求，先回答：它应该长什么样，我才能完成它？答不出来，后面全是瞎写。**

**跳掉这一步**：直接写 → 写出一个能跑的小功能 → 测试通过 → 报告「完成」→ 它只是系统里一小块，其余根本不存在。
**⇒ 病灶不是能力，是跳过「应然形态」。测试测不出来 —— 不存在的东西不产生红色。**

**AI 的注意力是概率决定的**，改提示词、加粗、重复都不保证它注意到。所以分两半：

```
软半  本文件 + references/   概率性   让模型知道怎么做
硬半  scripts/gate.sh        确定性   没做就不许过
```

**⇒ 软半只提高概率，硬半才保下限。每步都要产出文件 —— 文件能被机器读，注意力不能。**

## 铁律（C 认知 · G 闸门）

```
C1  核心问题是目标，不是标题。
C2  每个问题先定范畴（属于哪一层），再谈怎么解。
C3  量化是最后一步，不是分析方法。
C4  同一症状重复 ≥2 次 ⇒ 挖得不够深。停止修，回去重挖。
C5  不知道就搜。内部问题（这个设计对不对）也要搜。
C6  数据流 ≠ 信息流。只交出坐标 = 只交了数据流。
C7  范畴 ⊏ 完成。有范畴、有认知，仍然可能是 0。完成另算。
C8  测试只是依赖偏序的一条线性扩展。测试通过 ⇏ 完成。
C9  做法 = f(当前状态)，不是常量。越具体的计划，保质期越短。
C10 每条规则都要能指回一句话。指不回 = 四不像的零件。
C11 用户的原话是唯一权威。改写 = 换掉了权威，只剩你的理解。
C12 一个概念只许一处定义；第二处定义 = 下一次必然不同步。
C13 域先认来源：他给了就用他的，没给才推。说不出「删掉它会怎么坏」的不是域。
C14 判据里不许出现某个项目的词汇；写进去，它就只对一个项目有效。
C15 引导与兜底同轨：他一旦不判，兜底当场就上，不留空。
C16 规划与验收归任务发出者；子代理只执行 + 如实上报，不许自判通过。

G1  各步产物缺失，不许进下一步。
G2  集成面表有「不存在」，不许声称完成。
G3  验收没跑（退出码 0），不许声称完成。
G4  系统设计未签收，不许开程序设计段。
G5  探针红了，不许自己改探针 —— 先问另一个 AI，拿回依据再改。
G6  新文件必须落在落位表声明的某个位置；查不到就补表，不许裸放。
G7  立项后三定（位置结构 / 依赖序 / 风格）缺一，不许写业务代码。
G8  没有反证的判据不算判据（测不出红 = 永远为真）。
G9  立项不可判（表没填满 / 文档不存在 / 无边界 / 无未知项），不许开工。
G10 文档里出现补丁段（「原写…现改为…」「补记」），该文档按未完成处理。
G11 派活时写域没写清（哪些能改、哪些不许改），不许发任务。
G12 子代理的自验不算验收；lead 没写独立探针，不许判过。
```

**"Violating the letter of this rule is violating the spirit of it."**

## 主干：三个层，五道门

**这是本 skill 唯一的主干。所有步骤、切片、模板都挂在这里，不许另起一套。**

```
【层一·定向】一次，项目开始时做完
   ① 域        → 立项书：域表 + 边界 + 未知 + 兜底记录
   ② 逐域文档   → 每个域交一份（这就是「设计」，不是额外一步）
   ③ 三定       → 位置结构 / 依赖序 / 风格
   ④ 集成面     → 7 行接线清单：每片要知道自己接哪根线
   ⑤ 切片表     → 片 / 两个头 / 依赖 / 怎么算过
       │
       └─ 门 1 立项可判 ─ 门 2 域文档齐 ─ 门 3 设计可开工 ─ 门 4 切片可派

【层二·施工】每片循环，直到切片表走完
   ① 定规范 → ② 冻契约 → ③ lead 写探针 → ④ 派活
   → ⑤ 复跑 → ⑥ 双注入 → ⑦ 看两流 → ⑧ 记账 → ⑨ 只改状态
       └─ 门 5 一片可收

【收口】版本收尾
   对账（文档 ↔ 代码双向）+ 状态表 + 红线复核
```

**为什么 ② 必须单独列**：这个项目真正的成本在「九个域的文档各自写完」——
把这一步藏进「三定」里，就会出现「三定写完了，但域文档只有一半」而没人发现。

**为什么要 ④ 集成面在 ⑤ 切片表之前**：不知道每片接哪根线，切出来的片就是「能跑但接不上」。
集成面 7 行（入口 / 业务函数 / 接线 / 数据 / 失败路径 / 配置 / 可观测）就是每片的接线义务。

**五道门，缺一道不许进下一层**：

| 门 | 什么时候 | 判据 | 命令 |
|---|---|---|---|
| **1 立项可判** | ① 域表填完 | 表填满 / 无空列 / 路径在 / 有边界 / 未知项+怎么验 / 无补丁段 | `gate.sh <dir> --steps 0 --charter` |
| **2 域文档齐** | ② 逐域文档写完 | 每份文档存在且非空 / 不是空壳（有填满的表或 ≥3 个小节）/ 域表每行都有落点 | `gate.sh <dir> --steps 0 --domains` |
| **3 设计可开工** | ③ 三定写完 | 签收文件在且取舍非空 + 依赖序 / 依赖方向 / 风格带数字 | `gate.sh <dir> --steps 3` |
| **4 切片可派** | ④⑤ 都写完 | 集成面 7 行齐且无「不存在」+ 切片表填满 / 有反证 / 有依赖 / 无占位 | `gate.sh <dir> --steps 5 --board` |
| **5 一片可收** | 层二每片结束 | 验收退出码 0 + lead 独立探针 + 注入红点 | `gate.sh <dir> --done` |

**层一只做一次，层二循环 N 次。把层二的动作写进层一，或者把层一的推导塞进层二，都是越级。**

## 层一怎么走（三种来源，先认再推）

**域 = 范畴 = 「要让这件事成立，必须存在的一类东西」。先认来源，再决定要不要推。**

| 位置 | 一句话 | 唯一权威 |
|---|---|---|
| ① 认来源 | 他给了域清单 → 照他的建表；没给才推 | `r6` §2.2 |
| ② 推 | 功能 → 什么困境消失 → 必须同时有什么 | `r6` §2.3–§2.5 |
| ③ 划界 | 每域三件套 + 「删掉它会怎么坏」 | `r6` §3 |
| ④ 引导 ⇄ 兜底 | 同一个动作，不是先后两步（一问三备） | `r6` §4 |
| ⑤ 落实 | 不打补丁地写进文档（D1–D6） | `r6` §6 |

**三条不可忘的**：

```
他给了就照他的 —— 把他的清单重推成我的提案，是越权
问了必须有结局 —— 他判了 / 落了行业默认 / 进了未知项；第四种（问过、没结论、没记录）非法
答不成可判的话 ⇒ 是问法错了，不是用户不清
```

**② 逐域文档就是「设计」**：每域交三件套（管什么带反例 / 不管什么 / 怎么算过）+ 一份文档。
**过门 2（`--domains`）才算写完**：都存在、非空、不是空壳、域表每行有落点。
**这一步最容易被吞进「三定」里 —— 于是「三定写完了，域文档只有一半」。**

**③ 三定** 唯一权威 → `references/spacetime.md`；本文件只说一句：位置结构 / 依赖序 / 风格，缺一不许写业务代码。
**为什么测试不算数**：测试 = 一条确定的全序上打点；完成 = 偏序被全覆盖 ⇒ 测试通过 ⇏ 完成。

**④ 集成面** 7 行 + 探针 → `references/integration-surface.md`。**它排在切片表之前**：
不知道每片接哪根线，切出来就是「能跑但接不上」。

**⑤ 切片表** 四件东西（片 / 两个头 / 依赖 / 怎么算过）→ `references/r7-slice-board.md` §1。

**详规 → `r6-project-charter.md`（域与文档）· `spacetime.md`（三定）· `integration-surface.md`（集成面）· `r7`（切片）**

## 层二怎么走（一片九个动作）

① 先改规范（文档）→ ② 冻契约（子代理只填函数体）→ ③ lead 自己写独立探针 → ④ 派活（跨 crate 依赖串行 A→B，不并行）→ ⑤ 自己复跑（不信「全绿」）→ ⑥ 双注入（子代理一次 + lead 一次，红点必须不同）→ ⑦ 看两流（直接查库 / 直接读回）→ ⑧ 开发日志六节 → ⑨ 只改状态表一行。

**四条最贵的纪律**：

```
D-1 派活前跑一次基线，把真实数字抄进任务书（凭记忆 = 连续 8 次写错）
D-5 注入没红，先怀疑夹具覆盖不到，再怀疑实现
D-7 零覆盖检测：把主路径那一行注释掉，看有几条红；一条不红 = 零覆盖
D-8 重构要三类判据：快照（字节没变）+ wired（真调了）+ 计数（规则只剩 1 处）
```

**反套壳判据**：改库里一行，读回与落点必须跟着变；仍读回原串 = 读法被存了或查表拼的。
**分工与纪律全文 → `r8-slice-rhythm.md` §1–§3；切片与任务书 → `r7-slice-board.md`**

## 收口（版本级，不是片级）

```
1 文档 ↔ 代码双向对账（代码有、文档没写；文档写了、代码没有）——退出码 0
2 同一条规则在源码里的处数（grep 可数）——从 N 处降到 1 处
3 状态表只改那一行；红线逐条复核
4 未做的、违反的、欠的，明写在「债」里，不许藏
```

**⇒ 判据与实现不一致时只许两条路：改实现，或承认违反并写清代价。第三条路（改判据迁就实现）是自欺。**

## 四把尺（每个词与每个分类都要过）

**反例列**（词 / 定义 / 反例，否则「像」被当成「是」）· **穷举**（为什么只有这几种 + 第 N+1 种落在哪）· **同形词分离**（一词多义先裂开）· **不需要清单**（写清不需要什么 + 替代）。

**认知链四步**：① 锚（原话逐字 + 出处）→ ② 拆（A = B / 只有 N 种）→ ③ 推（一步一条「因此」）→ ④ 落（条文 + 一条可复算判据）。
**「不要写这种东西，有个屁用」= 形态被驳回**（他要条文，你在写分析）⇒ 改形态，不加解释。
**详规 → `r5-axiom-chain.md`**

## 八类入口（进来第一件事是判层，不是填表）

| # | 类 | 入口 | 最小产出 |
|---:|---|---|---|
| 1 | **认知**（认知不对 / 没有这层认知 / 四不像） | 认知链 | 原话账本 + 公理链 |
| 2 | **范畴**（定个范畴 / 术语不统一 / 边界在哪） | 层一·划界 | 范畴表 3 张表 |
| 3 | **立项**（立项 / 要不要做 / 从哪开始 / 立项即标准） | 层一·域 | 域表 + 边界 + 未知 + 兜底记录 |
| 4 | **规划**（分几步 / 里程碑 / 先做什么后做什么） | 层一·切片表 | 切片表（片 / 两流 / 依赖 / 怎么算过） |
| 5 | **策划**（方案 / 怎么落地 / 选哪个 / 代价） | 层一·策划 | 策划（≥2 备选 + 什么情况下会错 + 回滚） |
| 6 | **设计**（应该长什么样 / 部件怎么接 / 接口怎么定） | 层一·三定 | 设计（签收 + 三定） |
| 7 | **工程**（工程 / 架构 / 模块 / 依赖 / 重构 / 技术债） | 层一·三定 → 层二 | 三定 + 集成面 |
| 8 | **代码**（写代码 / 加个功能 / 报错了 / 测试过了） | 层二 | 九动作齐 + 门 4 |

**第 7、8 类最常被误以为"不用走流程"，也最常翻车 ⇒ 不许直接进"写"。**
**判层（不许一律从头）：已有立项不重写；三定齐 → 直接切片；缺范畴表 → 先划界；缺切片表 → 层二不许开。**
**完整判别法（含误伤防护、单点问题不许进门）→ `references/dispatch.md`（唯一权威）**

## 管不到的两块（不许含糊）

```

```

## 硬半怎么跑

```bash
SK=~/.dsh/skills/engineering-method          # 或 ~/.config/opencode/skills/...
bash $SK/scripts/gate.sh <项目目录>              # 八件 + G7 三定
bash $SK/scripts/gate.sh <项目目录> --steps 3,5  # 只查设计 / 集成面
bash $SK/scripts/gate.sh <项目目录> --done       # 加跑验收.sh（门 5）
bash $SK/scripts/gate.sh <项目目录> --arch       # 加查分类与落位
bash $SK/scripts/gate.sh <项目目录> --spiral     # 加查每轮新事实
bash $SK/scripts/gate.sh <项目目录> --charter    # 门 1：立项可判
bash $SK/scripts/gate.sh <项目目录> --domains    # 门 2：域文档齐
bash $SK/scripts/gate.sh <项目目录> --board      # 门 4：切片可派
```

**输出**：`PASS` / `BLOCK` + 缺什么。退出码 0 / 1 / 2（用法错）。**只读，绝不改任何文件。**
**模板**：`$SK/templates/`（立项书 / 文档宪法 / 切片表 / 任务书 / **开工单** / 开发日志 / 规划 / 策划 / 设计 / 范畴表 / 集成面 / 验收.sh / 反合理化表）。

## 三档约束（别自己加规则）

```
[gate] 代码强制：C/G 违规、五道门、三定、落位表、每条判据配反证
[soft] 靠判断力：核心问题句式、垂直切片、不变量可判真假、L3 含失败路径
[free] 明确不约束：格式、顺序、措辞、语言、篇幅、工具、图的形式
```

**`[free]` 是明写承诺：这些由执行者决定，后来者不得以「规范」为名加规则。**

## 十种失败

```
① 一致性代替真实性：A、B 同时改成同一个错值，检查结果不变
② 计数代替含义：数行数 / 覆盖率 / token，不解释结构
③ 数据流代替信息流：交出坐标，消费者推不出任何东西
④ 测试通过代替完成：测试是一条全序，完成是偏序闭合
⑤ 一次做到最好：不留螺旋记录 = 没有一轮产出新事实
⑥ 抄结论不抄前提：指不回任何一句前提 ⇒ 四不像
⑦ 文档数代替唯一权威：同一概念两处定义 ⇒ 下次必然不同步
⑧ 子代理报告代替验收：它说全绿，你没独立探针
⑨ 抄某个项目的形态当规范：九个域、七段、四列 —— 换个项目全废
⑩ 凭记忆写基线数字：任务书里的数没重跑（连续 8 次的坑）
```
