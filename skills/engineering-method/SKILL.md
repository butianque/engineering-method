# 工程方法论（分发层）

> **本文件只是"入口与索引"，不是手册。**
> 详细内容全部离散在 `references/` 里，**按需读，不要全读**。
>
> 这样做的理由：**塞进一个文件 = 必须压缩 = 有偿损失**。
> 拆成离散文件 + 精确指针 = **无损失，且只加载当下需要的那一片**。

---

## 核心（一句话）

> **拿到一个请求，先回答：它应该长什么样，我才能完成它？**
> **答不出来，后面全是瞎写。**

**跳掉这一步：**

```
用户提请求 → 不问"应然形态" → 直接写代码
          → 写出一个能跑的小功能 → 测试通过 → 报告"完成"
          → 它只是整个系统里的一小块，其余根本不存在
```

**⇒ 病灶不是能力，是跳过了「应然形态」。**
**⇒ 测试测不出来 —— 不存在的东西不产生红色。**

---

## 一条必须先接受的事实

**AI 的注意力是概率决定的。** 改提示词、加粗、重复都不能保证它注意到。

**⇒ 所以本 skill 分两半：**

| 半 | 载体 | 可靠性 | 作用 |
|---|---|---|---|
| **软半** | 本文件 + `references/` | **概率性** | 让模型知道该怎么做 |
| **硬半** | `scripts/gate.sh` | **确定性** | 没做就不许过 |

**⇒ 不要把希望放在软半。软半只提高概率，硬半才保下限。**
**⇒ 这也是为什么每一步都要产出**文件**：文件能被机器读，注意力不能。**

## 铁律（十三条）

```
C1  核心问题是目标，不是标题。
C2  每个问题先定范畴（属于哪一层），再谈怎么解。
C3  量化是最后一步，不是分析方法。
C4  同一症状重复 ≥2 次 ⇒ 挖得不够深。停止修，回去重挖。
C5  不知道就搜。内部问题（这个设计对不对）也要搜。
C6  数据流 ≠ 信息流。只交出坐标 = 只交了数据流。
C7  范畴 ⊏ 完成。有范畴、有认知，仍然可能是 0。完成另算。
C8  测试只是依赖偏序的一条线性扩展。测试通过 ⇏ 完成。
C9  做法 = f(当前状态)，不是常量。越具体的计划，保质期越短。

G1  各步产物缺失，不许进下一步。
G2  集成面表有「不存在」，不许声称完成。
G3  验收没跑（退出码 0），不许声称完成。
G4  系统设计未签收，不许开程序设计段。
G5  探针红了，不许自己改探针 —— 先交给另一个 AI 问，拿回依据再改。
G6  新文件必须落在落位表声明的某个位置；查不到就补表，不许裸放。
G7  立项后三定（位置结构 / 依赖序 / 风格）缺一，不许写业务代码。
```

**"Violating the letter of this rule is violating the spirit of it."**

## 立项后三定：AI 缺的是时间与空间

**这是本 skill 最要命的一段。** AI 的两个盲区可以精确到两行：

```
时间 = 依赖偏序 ⊑ 执行全序
       AI 只写全序（一行一行往下），从不校验偏序（谁先产生、谁先消费）

空间 = 人造物 → 已声明坐标，且坐标图是 DAG
       AI 只看见「文件」，不看见「节点在图里的位置」
```

**⇒ 立项之后的下一件事不是写代码，是定三样。缺一不许动业务代码。**

| # | 定什么 | 落到哪 | 判据 |
|---|---|---|---|
| **1** | **位置结构**（空间） | 落位表 + 模块依赖方向 | 每个新文件都能映射到某一行；依赖图无环 |
| **2** | **依赖序**（时间） | 依赖序图（谁产生→谁消费） | 执行序覆盖依赖序；无「执行先于依赖」 |
| **3** | **风格**（形式） | 风格契约（**必须带数字**） | 命名/嵌套/注释比例/函数长度，都可测 |

**为什么测试不算数（C8 的证明）：**

```
测试  = 在一条确定的执行全序上打点
完成  = 依赖偏序被全覆盖
⊑ 有无数条线性扩展，测试只钉住了其中一条
⇒ 测试通过 ⇏ 偏序闭合
```

**真实例证**：只改后端一处，`go test` 全绿，用户仍被踢。
因为「面板消费后端 401 reason」这条**偏序上的边**，不在任何一条 Go 测试的全序里。

**⇒ 所以：要的是真实数据流 + 信息流跑起来，不是测试变绿。**
`信息流 = ∅`（消费者拿到坐标推不出任何东西）⟹ 该链路未完成。

**详尽的定义、判据与常见违规 → `references/spacetime.md`**

| **范畴** | 定个范畴 / 术语不统一 / 边界在哪 | 步 4 | 范畴表 3 张表 |
| **立项** | 立项 / 要不要做 / 从哪开始 | 步 0 | 立项书 6 项 |
| **规划** | 规划 / 分几步 / 里程碑 | 步 1 | 立项书 + 规划.md |
| **策划** | 策划 / 方案 / 怎么落地 | 步 2 | 立项书 + 策划.md |
| **设计** | 设计 / 它应该长什么样 / 部件怎么接 | 步 3 | 立项书 + 设计.md（含签收 + 三定） |
| **工程** | 工程 / 架构 / 模块 / 分层 / 耦合 / 依赖 / 重构 / 技术债 / 跨仓库 | **步 3（三定）→ 步 5** | 设计.md 三定 + 集成面 |
| **代码** | 写代码 / 加个功能 / 改一下 / 报错了 / 测试过了 | **步 3 三定 → 步 5 → 步 6** | 三定齐 + 集成面无缺口 + 验收退出码 0 |

**「工程 / 代码」两类是最常被误以为"不用走流程"的，也是最常翻车的：**

```
「工程」问结构（模块/分层/依赖/技术债） → 答案必须落在三定里，不然是空谈
「代码」问动作（加/改/修）              → 动作前必须有三定，动作后必须有端到端
```

**⇒ 这两类不许直接进"写"，必须先进步 3 的三定（G7 的入口）。**

**判步（不许一律从步 0 开始）：**

```
已有 立项书？ 有 → 不重写
已有 设计（已签收 + 三定齐）？ 有 → 跳↻ 看缺口
已有 范畴表？ 没有 → 步 4
已有 集成面？ 没有 → 步 5
```

**⇒ 已有的一律不重写，只补缺的那一步。**
**判步的完整规则（含误伤防护、八类的判别法）→ `references/dispatch.md`**

## 螺旋：不必一次做到最好

**这一条是对「一次交付」的否定。**

```
[螺旋] = fix(λx. 实现(x) ⊗ 对账(x) ⊗ 加深(x))
         每轮必须产出一条「原来不知道的事实」，否则该轮无效
```

**螺旋不是迭代。差别在这里：**

| | 迭代 | 螺旋 |
|---|---|---|
| 每轮做什么 | 把同一件事做得更好 | **换一个更深的层** |
| 输入 | 上一轮的产出 | 上一轮产出 **+ 新事实** |
| 停在哪 | 满意为止 | **没有新事实可产为止** |
| 判据 | 更好了（没法判） | **这轮有新增维度吗（能判）** |

**⇒ 「每轮必须产出一条新事实」是螺旋的牙齿。**
**没有它，螺旋退化成原地迭代 —— 就是那个递归自我批判信息量衰减 55% 的现象。**

**每轮的最小形态：**

```
定一小块 → 立刻跑（不是攒到最后）→ 拿回一条新事实 → 用它改下一小块
```

**为什么必须"立刻跑"而不是"攒到最后"**：损伤在"只改不测"的窗口里会累积到不可修复。
（依据：PNAS 2022 模拟的加强结论，"分块"比"交替"差。）

**⇒ `gate.sh --spiral` 检查 `.runs/` 里每轮是否留下了新增事实条目。没有 = 该轮无效。**

## 五种最常见的失败

**① 用一致性代替真实性**：`A == B`，把 A、B 同时改成同一个错值，检查结果完全不变。
**② 用计数代替含义**：数行数、数覆盖率、数 token，而不解释结构。
**③ 用数据流代替信息流**：交出坐标（id / 路径 / 状态码），消费者推不出任何东西。

**④ 用测试通过代替完成**：测试是一条全序，完成是偏序闭合。前者通过不蕴含后者。
**⑤ 一次做到最好**：不留螺旋记录，等于没有一轮产出新事实，也就没有真进展。

## 一句话

> **你没法告诉 AI 它缺什么。**
> **但你可以让它看见：拆掉这个，天塌了。**
> **天塌了这件事它看得懂 —— 而且它必须为此造一个新词。**
