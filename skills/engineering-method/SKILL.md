# 工程方法论（分发层）

> **本文件只是"入口与索引"，不是手册。**
> 详细内容全部离散在 `references/` 里，**按需读，不要全读**。
> 理由：塞进一个文件 = 必须压缩 = 有偿损失；离散 + 精确指针 = 只加载当下需要的那一片。

---

## 核心（一句话）

> **拿到一个请求，先回答：它应该长什么样，我才能完成它？**
> **答不出来，后面全是瞎写。**

**跳掉这一步**：不问答然形态 → 直接写 → 写出一个能跑的小功能 → 测试通过 → 报告「完成」→ 它只是系统里一小块，其余根本不存在。

**⇒ 病灶不是能力，是跳过了「应然形态」。⇒ 测试测不出来——不存在的东西不产生红色。**

---

## 一条必须先接受的事实

**AI 的注意力是概率决定的。** 改提示词、加粗、重复都不保证它注意到。

| 半 | 载体 | 可靠性 | 作用 |
|---|---|---|---|
| **软半** | 本文件 + `references/` | 概率性 | 让模型知道怎么做 |
| **硬半** | `scripts/gate.sh` | 确定性 | 没做就不许过 |

**⇒ 软半只提高概率，硬半才保下限。每步都要产出文件——文件能被机器读，注意力不能。**

## 铁律（C 认知 · G 闸门）

```
C1  核心问题是目标，不是标题。
C2  每个问题先定范畴（属于哪一层），再谈怎么解。
C3  量化是最后一步，不是分析方法。
C4  同一症状重复 ≥2 次 ⇒ 挖得不够深。停止修，回去重挖。
C5  不知道就搜。内部问题（这个设计对不对）也要搜。
C6  数据流 ≠ 信息流。只交出坐标 = 只交了数据流。
C7  范畴 ⊏ 完成。有范畴、有认知，仍然可能是 0。完成另算。
C8  测试只是依赖偏序的一条线性扩展。测试通过 ⇏ 完成。
C9  做法 = f(当前状态)，不是常量。越具体的计划，保质期越短。
C10 每条规则都要能指回一句话。指不回 = 四不像的零件。
C11 用户的原话是唯一权威。改写 = 换掉了权威，只剩你的理解。
C12 一个概念只许一处定义；第二处定义 = 下一次必然不同步。
C13 域是推出来的，不是列出来的。说不出「删掉它会怎么坏」的不是域。
C14 判据里不许出现某个项目的词汇；写进去，它就只对一个项目有效。
C15 用户说不清 ⇒ 先改问法；还说不清 ⇒ 查行业（谁这么做 / 为什么 / 代价）。

G1  各步产物缺失，不许进下一步。
G2  集成面表有「不存在」，不许声称完成。
G3  验收没跑（退出码 0），不许声称完成。
G4  系统设计未签收，不许开程序设计段。
G5  探针红了，不许自己改探针 —— 先交给另一个 AI 问，拿回依据再改。
G6  新文件必须落在落位表声明的某个位置；查不到就补表，不许裸放。
G7  立项后三定（位置结构 / 依赖序 / 风格）缺一，不许写业务代码。
G8  没有反证的判据不算判据（测不出红 = 永远为真）。
G9  立项书缺域表 / 依赖顺序 / 落位表 / 裁决点，不许开工。
G10 文档里出现补丁段（「原写…现改为…」「补记」），该文档按未完成处理。
G11 派活时写域没写清（哪些能改、哪些不许改），不许发任务。
```

**"Violating the letter of this rule is violating the spirit of it."**

## 认知：从一句原话，到一条可复算的规则

**病灶：四不像 = 拿到了结论，没拿到生成结论的那个东西。**

```
用户：超边 = 节点。
抄结论 → 实现「去重」      → 用户：不需要去重，你根本没有这层认知
抄前提 → 同一性由结构给出  → 不需要 dedupe()，只需「已存在即复用」
```

**认知链四步，一步不许跳**：① 锚（原话逐字 + 出处）→ ② 拆（A = B / 只有 N 种）→ ③ 推（一步一条「因此」）→ ④ 落（条文 + 一条可复算判据）。

**四把尺（每个词与每个分类都要过）**：**反例列**（词 / 定义 / 反例，否则「像」被当成「是」）· **穷举**（为什么只有这几种 + 第 N+1 种落在哪）· **同形词分离**（一词多义先裂开，否则条文互相打架且各自都「对」）· **不需要清单**（写清不需要什么 + 用什么替代，否则范围无限涨）。

**「不要写这种东西，有个屁用」= 形态被驳回**（他要条文，你在写分析）⇒ 改形态，不加解释。
**详规 → `references/r5-axiom-chain.md`**

## 立项：域是推出来的，不是列出来的

**域 = 范畴 = 「要让这件事成立，必须存在的一类东西」。数量与名字由问题推出，不由模板给出。**

```
① 推   功能 → 什么困境消失 → 要成立必须同时有什么   得到候选域
② 划界 每域：管什么（带反例）/ 不管什么 / 怎么算过   得到边界与判据
③ 引导 把要求从用户嘴里提出来（他通常只说一半）      得到能判的条文
④ 兜底 用户不知道 ⇒ 问行业到底怎么做（谁这么做/为什么/代价）
⑤ 落实 不打补丁地写进文档
```

**判域的唯一标准**：删掉它，系统会以什么方式坏？说不出坏法 ⇒ 它是细节，不是域。

**引导的六种问法**（有效度排序）：两个选项各带代价 › 给行业默认让他否决 › 反推「不做会怎样」› 对齐他的原话 › 要一个可判判据 › 一次只问一个且立刻落条文。
**判据：每个问题都要能被答成一句可判的话；答不成 ⇒ 问法错了，不是用户不清。**

**不打补丁**：D1 只写当前真相 · D2 插入/替换/删除 · D3 一概念一处 · D4 文件只减不增 · D5 编号不复用 · D6 完成改状态不重读。

**判据必须形态无关**：查「表填满了没 / 路径通不通 / 边界写了没 / 有没有未知项 / 有没有补丁段」，不查「有没有域表这一节」「是不是九个域」——写进项目词汇，判据就只对一个项目有效。
**详规 → `references/r6-project-charter.md`**

## 立项后三定：AI 缺的是时间与空间

**这是本 skill 最要命的一段。AI 的两个盲区，可以精确到两行：**

```
时间 = 依赖偏序 ⊑ 执行全序   AI 只写全序（一行行往下），从不校验偏序（谁先产生、谁先消费）
空间 = 人造物 → 已声明坐标   AI 只看见「文件」，不看见「节点在图里的位置」
```

**⇒ 立项之后的下一件事不是写代码，是定三样。缺一不许动业务代码。**

| # | 定什么 | 落到哪 | 判据 |
|---|---|---|---|
| **1** | **位置结构**（空间） | 落位表 + 模块依赖方向 | 每个新文件都能映射到某一行；依赖图无环 |
| **2** | **依赖序**（时间） | 依赖序图（谁产生→谁消费） | 执行序覆盖依赖序；无「执行先于依赖」 |
| **3** | **风格**（形式） | 风格契约（**必须带数字**） | 命名/嵌套/注释比例/函数长度，都可测 |

**为什么测试不算数（C8 的证明）**：测试 = 在一条确定的全序上打点；完成 = 依赖偏序被全覆盖；偏序有无数条线性扩展，测试只钉住其中一条 ⇒ 测试通过 ⇏ 偏序闭合。

**真实例证**：只改后端一处，`go test` 全绿，用户仍被踢。
因为「面板消费后端 401 reason」这条**偏序上的边**，不在任何一条 Go 测试的全序里。

**⇒ 所以：要的是真实数据流 + 信息流跑起来，不是测试变绿。**
`信息流 = ∅`（消费者拿到坐标推不出任何东西）⟹ 该链路未完成。

**详尽的定义、判据与常见违规 → `references/spacetime.md`**

## 切片与派活：一次只开一片

**一片 = 一条能从输入走到行、再从行走回语义的功能。走不到两头的，是半片。**

切片表四列：片 / 功能 / 数据流出口 / 信息流出口 / 依赖；顺序写成一行；重构片标「行为不变」，测试条数改前改后须相等。
每片四问：数据流怎么走 / 信息流怎么回 / 落在哪个文件 / 怎么算过（判据 + 反证）。
**反套壳判据**：删掉成因那一行，读回必须变短或失败；仍「正常」= 读法被存了或查表拼的。

任务书九段：环境 / 唯一权威+节号 / 写域（只许改·不许改）/ 冻结契约 / 语义 A1…An / 测试一编号一测试 / **反证注入必红** / 禁止（todo!/硬编码/吞错误）/ 交付报告必含 + `blocked_by` + `write_scopes`。
**lead 三件事**：冻结骨架自己写 · 自己写验收探针 · 逐条验收（语义属实 / 不是套壳 / 不是查表）。
**报告里最该看的不是「通过」，是「我改了几处、原写法 → 新写法 → 为什么」。** 详规 → `references/r7-slice-board.md`

## 螺旋：不必一次做到最好

**这一条是对「一次交付」的否定。**

```
[螺旋] = fix(λx. 实现(x) ⊗ 对账(x) ⊗ 加深(x))     每轮必须产出一条「原来不知道的事实」
```

**螺旋不是迭代**：迭代 = 同一件事做得更好、满意为止；螺旋 = 换一个更深的层、没有新事实可产为止。
**每轮最小形态**：定一小块 → 立刻跑（不攒）→ 拿回一条新事实 → 改下一小块。（为啥不攒：损伤在「只改不测」的窗口里累积到不可修复；依据 PNAS 2022）

**⇒ `gate.sh --spiral` 查 `.runs/spiral.md` 每轮有没有新增事实条目。没有 = 该轮无效。**

| 检查点 | 判据 | 谁判 |
|---|---|---|

## 硬半怎么跑

```bash
SK=~/.dsh/skills/engineering-method          # 或 ~/.config/opencode/skills/...

bash $SK/scripts/gate.sh <项目目录>              # 查全部八件 + G7 三定
bash $SK/scripts/gate.sh <项目目录> --steps 3,5  # 只查设计（签收+三定）/ 集成面
bash $SK/scripts/gate.sh <项目目录> --done       # 加跑验收.sh
bash $SK/scripts/gate.sh <项目目录> --arch       # 加跑分类与落位
bash $SK/scripts/gate.sh <项目目录> --spiral     # 加查每轮新事实
bash $SK/scripts/gate.sh <项目目录> --charter    # 加查立项（只查结构，不查词汇）
bash $SK/scripts/gate.sh <项目目录> --board      # 加查切片（只查结构，不查词汇）
```

**输出**：`PASS` / `BLOCK` + 缺什么。退出码 0 / 1 / 2（用法错）。

**模板**：`$SK/templates/` 下有 11 份中文模板（立项书 / 规划 / 策划 / 设计 / 范畴表 / 集成面 / 验收.sh / 反合理化表 / 文档宪法 / 切片表 / 任务书），另有证明类 5 份。

## 三档约束（别自己加规则）

```
[gate] 代码强制：C/G 违规处置、各步产物、设计签收、三定、落位表、螺旋、立项可判、每条判据配反证
[soft] 靠判断力：核心问题句式、垂直切片、不变量可判真假、L3 含失败路径
[free] 明确不约束：格式、顺序、措辞、语言、篇幅、工具、图的形式
```

**`[free]` 是明写承诺：这些由执行者决定，后来者不得以"规范"为名加规则。**

## 九种最常见的失败

**① 一致性代替真实性**：把 A、B 同时改成同一个错值，检查结果完全不变。
**② 计数代替含义**：数行数、覆盖率、token，不解释结构。
**③ 数据流代替信息流**：交出坐标，消费者推不出任何东西。
**④ 测试通过代替完成**：测试是一条全序，完成是偏序闭合。
**⑤ 一次做到最好**：不留螺旋记录 = 没有一轮产出新事实。
**⑥ 抄结论不抄前提**：规则齐、判据齐，但指不回任何一句公理 ⇒ 四不像。
**⑦ 文档数代替唯一权威**：同一概念两处定义 ⇒ 下次必然不同步。
**⑧ 子代理报告代替验收**：它说全绿，你没独立探针 ⇒ 套壳、查表、硬编码都过得去。
**⑨ 抄某个项目的形态当规范**：九个域、七段、四列 —— 换个项目全废，还会逼着人硬凑。
