# 工程方法论（分发层）

> **本文件只是"入口与索引"，不是手册。**
> 详细内容全部离散在 `references/` 里，**按需读，不要全读**。
> 理由：塞进一个文件 = 必须压缩 = 有偿损失；离散 + 精确指针 = 只加载当下需要的那一片。

---

## 核心（一句话）

> **拿到一个请求，先回答：它应该长什么样，我才能完成它？答不出来，后面全是瞎写。**

**跳掉这一步**：直接写 → 写出一个能跑的小功能 → 测试通过 → 报告「完成」→ 它只是系统里一小块，其余根本不存在。
**⇒ 病灶不是能力，是跳过「应然形态」。测试测不出来 —— 不存在的东西不产生红色。**

---

## 一条必须先接受的事实

**AI 的注意力是概率决定的** —— 改提示词、加粗、重复都不保证它注意到。所以本 skill 分两半：

```
软半  本文件 + references/   概率性   让模型知道怎么做
硬半  scripts/gate.sh        确定性   没做就不许过
```

**⇒ 软半只提高概率，硬半才保下限。每步都要产出文件 —— 文件能被机器读，注意力不能。**

## 铁律（C 认知 · G 闸门）

```
C1  核心问题是目标，不是标题。
C2  每个问题先定范畴（属于哪一层），再谈怎么解。
C3  量化是最后一步，不是分析方法。
C4  同一症状重复 ≥2 次 ⇒ 挖得不够深。停止修，回去重挖。
C5  不知道就搜。内部问题（这个设计对不对）也要搜。
C6  数据流 ≠ 信息流。只交出坐标 = 只交了数据流。
C7  范畴 ⊏ 完成。有范畴、有认知，仍然可能是 0。完成另算。
C8  测试只是依赖偏序的一条线性扩展。测试通过 ⇏ 完成。
C9  做法 = f(当前状态)，不是常量。越具体的计划，保质期越短。
C10 每条规则都要能指回一句话。指不回 = 四不像的零件。
C11 用户的原话是唯一权威。改写 = 换掉了权威，只剩你的理解。
C12 一个概念只许一处定义；第二处定义 = 下一次必然不同步。
C13 域先认来源：他给了就用他的，没给才推。说不出「删掉它会怎么坏」的不是域。
C14 判据里不许出现某个项目的词汇；写进去，它就只对一个项目有效。
C15 引导与兜底同轨：他一旦不判，兜底当场就上，不留空。
C16 规划与验收归任务发出者；子代理只执行 + 如实上报，不许自判通过。

G1  各步产物缺失，不许进下一步。
G2  集成面表有「不存在」，不许声称完成。
G3  验收没跑（退出码 0），不许声称完成。
G4  系统设计未签收，不许开程序设计段。
G5  探针红了，不许自己改探针 —— 先问另一个 AI，拿回依据再改。
G6  新文件必须落在落位表声明的某个位置；查不到就补表，不许裸放。
G7  立项后三定（位置结构 / 依赖序 / 风格）缺一，不许写业务代码。
G8  没有反证的判据不算判据（测不出红 = 永远为真）。
G9  立项不可判（表没填满 / 文档不存在 / 无边界 / 无未知项），不许开工。
G10 文档里出现补丁段（「原写…现改为…」「补记」），该文档按未完成处理。
G11 派活时写域没写清（哪些能改、哪些不许改），不许发任务。
G12 子代理的自验不算验收；lead 没写独立探针，不许判过。
```

**"Violating the letter of this rule is violating the spirit of it."**

## 认知：从一句原话，到一条可复算的规则

**病灶：四不像 = 拿到了结论，没拿到生成结论的那个东西。**

```
用户：超边 = 节点。
抄结论 → 实现「去重」→ 用户：不需要去重，你根本没有这层认知
抄前提 → 同一性由结构给出 → 不需 dedupe()，只需「已存在即复用」
```

**认知链四步，一步不许跳**：① 锚（原话逐字 + 出处）→ ② 拆（A = B / 只有 N 种）→ ③ 推（一步一条「因此」）→ ④ 落（条文 + 一条可复算判据）。

**四把尺**：**反例列**（词 / 定义 / 反例，否则「像」被当成「是」）· **穷举**（为什么只有这几种 + 第 N+1 种落在哪）· **同形词分离**（一词多义先裂开，否则条文互相打架且各自都「对」）· **不需要清单**（写清不需要什么 + 替代，否则范围无限涨）。

**「不要写这种东西，有个屁用」= 形态被驳回**（他要条文，你在写分析）⇒ 改形态，不加解释。
**详规 → `references/r5-axiom-chain.md`**

## 立项：域就是范畴，先认来源再推

**域 = 范畴 = 「要让这件事成立，必须存在的一类东西」。先认来源，再决定要不要推。**

```
① 认来源 用户给了域清单吗？给了就照他的建表，你只补「管什么/不管什么/怎么算过」
② 推     没给才推：功能 → 什么困境消失 → 必须同时有什么
③ 划界   每域三件套 + 「删掉它会怎么坏」（说不出 ⇒ 它是细节，不是域）
④ 引导⇄兜底  同一个动作，不是先后两步（见下）
⑤ 落实   不打补丁地写进文档（D1–D6）
```

**引导 ⇄ 兜底 同轨（一问三备）**：① 两个选项各带代价 → 他判了用他的；② 他不判 → 落行业默认并标明；③ 他都不接受 → 反推「不做会怎样」定边界。
**结局只有三种：他判了 / 落了行业默认 / 进了未知项。第四种（问过、没结论、没记录）非法。**
**判据：每个问题都要能被答成一句可判的话；答不成 ⇒ 问法错了，不是用户不清。** 行业兜底不许写「一般来说」，要说得出 谁这么做 / 为什么 / 代价。

**不打补丁**：D1 只写当前真相 · D2 插入/替换/删除 · D3 一概念一处 · D4 文件只减不增 · D5 编号不复用 · D6 完成改状态不重读。
**判据必须形态无关**：查结构（表填满没 / 路径通不通 / 边界有没 / 未知项有没 / 补丁段有没），不查某个项目的词汇。
**详规 → `references/r6-project-charter.md`**

## 立项后三定：AI 缺的是时间与空间

**AI 的两个盲区，精确到两行**：

```
时间 = 依赖偏序 ⊑ 执行全序   AI 只写全序（一行行往下），从不校验偏序（谁先产生、谁先消费）
空间 = 人造物 → 已声明坐标   AI 只看见「文件」，不看见「节点在图里的位置」
```

**⇒ 立项之后的下一件事不是写代码，是定三样。缺一不许动业务代码。**

| # | 定什么 | 落到哪 | 判据 |
|---|---|---|---|
| **1** | **位置结构**（空间） | 落位表 + 模块依赖方向 | 每个新文件能映射到某一行；依赖图无环 |
| **2** | **依赖序**（时间） | 依赖序图（谁产生→谁消费） | 执行序覆盖依赖序；无「执行先于依赖」 |
| **3** | **风格**（形式） | 风格契约（**必须带数字**） | 命名/嵌套/注释比例/函数长度，都可测 |

**为什么测试不算数（C8）**：测试 = 在一条确定的全序上打点；完成 = 偏序被全覆盖；偏序有无穷多条线性扩展，测试只钉住其中一条 ⇒ 测试通过 ⇏ 偏序闭合。
**真实例证**：只改后端一处，`go test` 全绿，用户仍被踢 —— 「面板消费后端 401 reason」这条偏序上的边，不在任何一条 Go 测试的全序里。

**⇒ 要的是真实数据流 + 信息流跑起来，不是测试变绿。`信息流 = ∅` ⟹ 该链路未完成。详规 → `references/spacetime.md`**

## 切片与派活：一次只开一片

**一片 = 一条能从输入走到行、再从行走回语义的功能。走不到两头的，是半片。**

**九个动作，顺序不许换**：① 先改规范（文档）→ ② 冻契约（子代理只填函数体）→ ③ lead 自己写独立探针 → ④ 派活（跨 crate 依赖串行 A→B，不并行）→ ⑤ 自己复跑（不信「全绿」）→ ⑥ 双注入（子代理一次 + lead 一次，红点不同）→ ⑦ 看两流（直接查库 / 直接读回）→ ⑧ 开发日志六节 → ⑨ 只改状态表一行。

**四条最贵的纪律**：

```
D-1 派活前跑一次基线，把真实数字抄进任务书（凭记忆 = 连续 8 次写错）
D-5 注入没红，先怀疑夹具覆盖不到，再怀疑实现
D-7 零覆盖检测：把主路径那一行注释掉，看有几条红；一条不红 = 零覆盖
D-8 重构要三类判据：快照（字节没变）+ wired（真调了）+ 计数（规则只剩 1 处）
```

**分工是硬的，没有例外**：子代理只执行派给它的任务，**不验收**；规划与验收归任务发出者；子代理有问题可如实上报（冲突 / 越界 / 做不到），但**不许下「通过 / 完成」**。连「纯搬运」也不许交给它自验 —— 搬运最容易悄悄改掉字节，只有 lead 的逐字节快照能抓。

**反套壳判据**：改库里一行，读回与落点必须跟着变；仍读回原串 = 读法被存了或查表拼的。
**详规 → `references/r7-slice-board.md` · `references/r8-slice-rhythm.md`**

## 螺旋：不必一次做到最好

```
[螺旋] = fix(λx. 实现(x) ⊗ 对账(x) ⊗ 加深(x))     每轮必须产出一条「原来不知道的事实」
```

**螺旋不是迭代**：迭代 = 同一件事做得更好、满意为止；螺旋 = 换一个更深的层、没有新事实可产为止。
**每轮最小形态**：定一小块 → 立刻跑（不攒）→ 拿回一条新事实 → 改下一小块。（不攒的理由：损伤在「只改不测」的窗口里累积到不可修复）

**⇒ `gate.sh --spiral` 查 `.runs/spiral.md` 每轮有没有新增事实条目。没有 = 该轮无效。**

## 八个不能省的检查点

| 检查点 | 判据 | 谁判 |
|---|---|---|
| **立项可判** | 表被填满 / 声明文档在 / 有边界 / 有未知项+怎么验 / 无补丁段 | `--charter` G9·G10 |
| **设计签收** | `.runs/signoff-system-design.md` 存在且"取舍"栏非空 | G4 |
| **三定齐** | 依赖序图（有覆盖列）/ 模块依赖方向 / 风格契约（带数字） | G7 |
| **分类与落位** | 落位表 + 新文件都能映射到某一行 | `--arch` G6 |
| **集成面无缺口** | 7 行齐 / 无「不存在」/ 探针非空 | G2 |
| **切片可派** | 表填满 / 有反证 / 有依赖 / 无占位 | `--board` G11 |
| **验收退出码** | `bash 验收.sh` 返回 0 | G3 |
| **螺旋有新事实** | 每轮记了「原来不知道的事实」 | `--spiral` G8 |

**其余步骤缺失 → G1 拦；探针红了想改探针 → G5（先问 AI2，见 `references/ai2-handoff.md`）。**

**管不到的两块（不许含糊）**：时空能管「写跨界边 / 每条边配全序 / 依赖图是 DAG」，管不到「算不算跨界」；统筹能管「落位表 / 新文件落在已声明位置」，管不到「需要新类」「命名」。详见 `spacetime.md` · `placement.md`。

## 硬半怎么跑

```bash
SK=~/.dsh/skills/engineering-method          # 或 ~/.config/opencode/skills/...
bash $SK/scripts/gate.sh <项目目录>              # 八件 + G7 三定
bash $SK/scripts/gate.sh <项目目录> --steps 3,5  # 只查设计 / 集成面
bash $SK/scripts/gate.sh <项目目录> --done       # 加跑验收.sh
bash $SK/scripts/gate.sh <项目目录> --arch       # 加查分类与落位
bash $SK/scripts/gate.sh <项目目录> --spiral     # 加查每轮新事实
bash $SK/scripts/gate.sh <项目目录> --charter    # 加查立项（只查结构）
bash $SK/scripts/gate.sh <项目目录> --board      # 加查切片（只查结构）
```

**输出**：`PASS` / `BLOCK` + 缺什么。退出码 0 / 1 / 2（用法错）。

**模板**：`$SK/templates/` 下 12 份中文模板（立项书 / 规划 / 策划 / 设计 / 范畴表 / 集成面 / 验收.sh / 反合理化表 / 文档宪法 / 切片表 / 任务书 / 开发日志），另有证明类 5 份。

## 三档约束（别自己加规则）

```
[gate] 代码强制：C/G 违规、各步产物、签收、三定、落位表、螺旋、立项可判、每条判据配反证
[soft] 靠判断力：核心问题句式、垂直切片、不变量可判真假、L3 含失败路径
[free] 明确不约束：格式、顺序、措辞、语言、篇幅、工具、图的形式
```

**`[free]` 是明写承诺：这些由执行者决定，后来者不得以「规范」为名加规则。**

## 十种最常见的失败

**① 一致性代替真实性**：A、B 同时改成同一个错值，检查结果不变。
**② 计数代替含义**：数行数、覆盖率、token，不解释结构。
**③ 数据流代替信息流**：交出坐标，消费者推不出任何东西。
**④ 测试通过代替完成**：测试是一条全序，完成是偏序闭合。
**⑤ 一次做到最好**：不留螺旋记录 = 没有一轮产出新事实。
**⑥ 抄结论不抄前提**：规则齐、判据齐，但指不回任何一句前提 ⇒ 四不像。
**⑦ 文档数代替唯一权威**：同一概念两处定义 ⇒ 下次必然不同步。
**⑧ 子代理报告代替验收**：它说全绿，你没独立探针 ⇒ 套壳、查表、硬编码都过得去。
**⑨ 抄某个项目的形态当规范**：九个域、七段、四列 —— 换个项目全废，还逼着人硬凑。
**⑩ 凭记忆写基线数字**：任务书里的数没重跑 ⇒ 子代理拿错起点（连续 8 次的坑）。
