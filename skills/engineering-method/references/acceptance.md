# 验收：三级，缺一级不算完

> 单测通过 ≠ 能用。这一份讲清 L3 怎么写，以及"端点全覆盖"怎么做。

---

## 一、三级的分工

| 级 | 回答什么问题 | 通过标准 | 不能替代谁 |
|---|---|---|---|
| **L1 语法** | 代码能编译吗 | 退出码 0 | 不能替代 L2（能编译不代表逻辑对） |
| **L2 单测** | 每个函数行为对吗 | 退出码 0 + 至少一条新测试先红后绿 | 不能替代 L3（函数对不代表链路通） |
| **L3 端到端** | 从外面打得通吗 | 退出码 0 + 断言了响应体/产物 | **没有替代** |

**⇒ 三级不是"越往后越高级"，是三个不重叠的问题。**

---

## 二、L2 的关键：先红后绿

**「测试通过了」这句话，只有在你看见它先失败过，才有意义。**

```
写测试 → 跑 → 红（证明它能抓到问题）
        → 改代码 → 跑 → 绿（证明修对了）
```

**只看到绿 = 不知道这个测试有没有约束力。**

**⇒ 判据**：
```
新测试必须在没有实现时红过一次。
没红过的测试 = 可能永远是绿的 = 没有约束力。
```

**反例**（真实发生过）：一个测试断言"某函数在第 115 行"，但第 115 行是注释。
它永远是红的，也永远不看代码对不对 —— 它测的是行号，不是行为。

---

## 三、L3 的三条硬要求

```
E1  必须从真实入口：HTTP / CLI / UI，不许直接调函数
E2  必须断言期望结果，不只是"没报错"
E3  端点清单里每一个都要打一次（漏一个 = 漏测一个）
```

### E1 为什么不能直接调函数

**直接调函数 = 跳过了路由、中间件、序列化、鉴权。**
**而这四层正是最容易出问题的地方。**

> 真实案例：一次修复中，函数级测试全绿，
> 但请求经过中间件时被一个陈旧令牌打成 401。
> **函数根本不知道中间件在前面。**

### E2 为什么不能只断言"没报错"

```bash
# ❌ 只证明它回了个东西
curl -sf "$BASE/api/x" > /dev/null

# ✅ 证明它回对了
curl -s "$BASE/api/x" | grep -q '"ok":true'
```

**"200 但数据是错的"是最难发现的失败**，只有断言内容才能抓。

### E3 怎么做到端点全覆盖

**做法**：从路由注册处导出端点清单，逐个打。

```bash
# 例：Go 项目从路由表导出
grep -rhoE '\.(GET|POST|PUT|PATCH|DELETE)\("([^"]+)"' internal/api/ \
  | sed -E 's/.*\("([^"]+)".*/\1/' | sort -u > .runs/routes.txt

# 逐个打（期望不是 404）
while read -r p; do
  code=$(curl -s -o /dev/null -w '%{http_code}' "$BASE$p")
  [ "$code" = "404" ] && echo "MISSING $p" || echo "ok $p ($code)"
done < .runs/routes.txt
```

**判据**：清单里没有 404，且每个端点的期望状态码被单独断言过。

**为什么这条重要**：只打一个端点，漏写的端点不红。
**这是 PRP 那套 L3 的缺口，也是我们的补丁。**

## 四、必须包含一条失败路径

**只测成功路径的验收，等于没测错误处理。**

| 场景 | 期望 |
|---|---|
| 空 body | 400，不是 500 |
| 缺必填字段 | 400，且错误信息指明哪个字段 |
| 越权 | 401/403，不是 200 |
| 超长输入 | 400 或被截断，不是 OOM |

**判据**：`验收.sh` 里至少有一条故意传错的用例，且断言了具体的错误码/文案。

## 五、脚本骨架

见 `templates/验收.sh`。三级结构已给，填自己的命令即可。

**跑法**：

```bash
bash 验收.sh              # 全跑
bash 验收.sh --case e2e   # 只跑 L3
```

**输出约定**：每级打印 `ok` / `FAIL`，最后打印 `ACCEPT` 或 `REJECT`。

---

## 六、验收跑不通时怎么排查

**顺序不能反：**

```
1  先确认服务真在跑（curl /health）
2  再看是不是环境问题（端口、环境变量、数据库）
3  再看是不是数据问题（库里有没有前置数据）
4  最后才怀疑代码
```

**为什么**：前三类占失败原因的绝大多数，而它们**跟代码无关**。
跳过前三步直接改代码，是最常见的浪费。

---

## 七、诚实边界

**L3 只能断言你写出来的断言。**
**没写的端点、没想到的失败模式，L3 不会红。**

**⇒ 所以 L3 覆盖的是"你想到的那部分"。**
**剩下那部分，靠集成面表（`02-integration-surface.md`）和悬置审计**。
