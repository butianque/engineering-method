# AI+AI 交接：撞墙 → 问 → 回写成约束

> 这是"24 小时自动化"的唯一形态。
> **核心判断：问题不能由 AI 生成，必须由墙生成；墙必须由机器造；问题必须由模板成型。**

---

## 一、触发：只在撞墙时

```
❌ "AI1 觉得需要问"  → 需要元认知 → AI 没有 → 不可实现
✅ "AI1 撞墙"        → 客观信号   → 有     → 可实现
```

**墙的五种来源（全部由机器产生，AI1 不参与）：**

| 墙源 | 怎么来 |
|---|---|
| 编译 / 测试 / lint | 跑命令，退出码非 0 |
| 端到端探针 | 从外部入口打一发，看状态码/产物 |
| 断裂注入 | 拆一个接缝，跑一遍，看断不断 |
| 真机异常 | 生产日志 / 超时 / 4xx-5xx |
| 对账缺口 | 集成面表里还有 `不存在` |

**判据**：
```
一个 AI+AI 系统，如果一天下来没产出任何一条墙 —— 它今天什么也没学到。
```

---

## 二、七字段模板（AI1 不许改写措辞）

```
【墙】      <编译 / 500 / 超时 / 数据不符 / 接缝断裂>
【位置】    <文件:行号 | 路由 | 表.列>
【最小复现】 <命令 | 请求 | diff hunk>
【期望】    <应当发生什么>
【实际】    <发生了什么>
【我试过】  <最多 3 条，每条必须带命令>
【不许做的】 <不许改探针、不许删断言、不许 mock、不许改超时>
```

**为什么必须由模板生成**：

```
让 AI1 自由描述 → 它用已有范畴说成"这里有个 bug"
                 → AI2 只能在这个框架里想
                 → 换框架失败 = 镜屋
```

**`【我试过】` 必须带命令。** "我分析认为"不算。

---

## 三、AI2 必须换框架（这是全部价值所在）

**同一个框架 = 镜屋。** 有实验数据：无外部反馈的递归自我批判，信息量衰减 55%；
带外部验证则 +28% 反弹（arXiv:2510.21861，三家 provider 一致）。

| AI1 的框架 | AI2 必须换成的框架 |
|---|---|
| 怎么让这个功能工作 | **这条链路还缺哪几件事** |
| 这个报错怎么修 | **这个报错说明谁的假设错了** |
| 测试怎么过 | **测试测的是不是对的东西** |
| 代码怎么写 | **从外部入口打得通吗** |
| 这个实现对不对 | **用户拿到的是什么** |

**⇒ 换框架不是"换个说法"，是换画布。**
**⇒ 如果 AI2 的答案能用 AI1 的原话说出来，说明它没换框架，作废重问。**

---

## 四、AI2 的输出格式（缺字段 = 无效）

```json
{
  "结论": "...",
  "依据": [
    "internal/api/handlers/management/sessions.go:432",
    "命令: grep -n 'belongsToCurrentConnection' web/src/services/api/client.ts → 命中 1 处"
  ],
  "不确定项": ["还有哪些调用点没查", "..."]
}
```

**硬要求（三条）：**

```
A1  「依据」必须非空。空 = 无效回答，重跑一次；仍空 = 标 degraded + 报警
A2  「依据」必须是文件:行号 或 命令输出，不许是"经验上认为"
A3  ：「不确定项」必须填。填"无"要求说明为什么能确定
```

**为什么要 A3**：让第二次问有方向。也让"看起来答了其实没答"露出来。

## 五、回写：这是"学习"与"聊天"的分界

| 强度 | 通道 | 算不算学习 |
|---|---|---|
| 弱 | 写进对话 | ❌ 下次就忘了 |
| 中 | 写进 notes | ⚠️ 下次可能读到，也可能不读 |
| **强** | **写进判据读的文件**（集成面表 / 探针清单 / 验收脚本） | ✅ **不满足就不许过** |

**⇒ 只有"强"这一档算学习。**

**具体怎么回写：**

| AI2 说 | 回写到哪 |
|---|---|
| "这条链路还缺 X" | 集成面表新增一行，状态 `不存在` |
| "这个端点没被测" | 验收脚本新增一条用例 |
| "这个探针测的不是它想测的" | 改探针 + 在 `.runs/` 记一条 |
| "这个不变量不成立" | 范畴表改不变量，或改实现 |

**⇒ 回写之后必须重跑 gate。** 没跑 = 没回写。

## 六、有界 + 换位

### 有界

```
最多 N 轮（N 由代码定，不由模型定）
最后一轮仍失败 ⇒ 具名出口 judge_blocked，exitCode 非 0
                 （不许伪装成 completed）
```

**为什么强调"具名出口"**：有过真实教训 ——
最后一轮判据拒绝了，但出口写的是 `completed`，脚本被骗。

### 换位

```
第 1 轮：AI1 执行，AI2 质疑
第 2 轮：AI2 执行，AI1 质疑   ← 对调
```

**为什么要对调**：同一个 AI 一直在执行位，它的框架会固化。
换到质疑位，它被迫用另一套框架看同一份东西。
**这是内部唯一能造出的"框架差"。**

---

## 七、成本控制

**每次撞墙一次完整调用，很贵。按优先级排：**

| 优先级 | 依据 |
|---|---|
| 高 | 被多处依赖的（约束密度高 = 承重墙） |
| 高 | 会导致数据丢失的 |
| 中 | 会导致接口不兼容的 |
| 低 | 只是少了日志/注释 |

**⇒ 先问高优先级的墙。低优先级的攒着批量问。**

---

## 八、诚实边界

**AI2 也可能是错的。**

**⇒ 兜底只能是"不说话的判据"：**
**探针、退出码、编译结果。AI2 可以错，`exit 0` 不会错。**

**⇒ 所以这个环路里，AI2 负责"提出新假设"，机器负责"否掉错的假设"。**
**顺序不能反。**

---

## 九、自检

- [ ] 触发点是墙，不是"我觉得"
- [ ] 用了七字段模板，没改写
- [ ] AI2 的框架与 AI1 不同
- [ ] AI2 的回答带文件:行号 或命令输出
- [ ] 答案回写进了判据读的文件
- [ ] 回写后重跑了 gate
- [ ] 有轮次上限，且失败有具名出口
