# 实战案例集

两个完整案例，都是从**用户原话**到**工程落地**的全过程。
读它们比读规则快 —— 规则是结论，案例是推理。

---

## 案例 A：「接口太僵硬」→ 站位机制从没接出去

### A.1 用户原话

> 「接口读取站位其实只有一个，有且只有一个。也就是注意力站位这个系统机制。
> 也就是核心站位+N个补充站位的机制。
> 你所说的N走几步，这是动态注意力机制的即时局部注意力。
> 换句话说来说其实都是一致的。
> 接口如果说是这样写，僵硬程度可想而知。」

### A.2 我是怎么走错的（先记错，再记对）

| 我的判断 | 实际 | 怎么发现的 |
|---|---|---|
| 「接口只吐裸坐标，AI 什么也拿不到」 | `/api/memory` 早就有 `reading` 了 | 派了两路调研，第一路直接打脸 |
| 「要新造一个主接口」 | 那个词在库里**不是实体**，压根没法「站」在上面 | 自己跑了一遍节点表，发现没有「苹果」这一项 |
| 「加一个字段就够」 | 不够。真正致命的是一端是 `0` | 调研指出 + 自己实测 |

### A.3 递归路径

```
【核心问题】接口为什么「僵硬」？
├─ [L4 接口] 为什么只有最底层的原语被暴露？
│    └─ 机制：上层模型被拆成两半 —— 
│         A 管「链」（核心+补充），B 管「候选」（关注点+关系）
│         A 没有「取候选」的方法，B 不知道链 ⇒ 谁也接不上谁
│         结果：接口退回单个原语
│    └─ 证据：`grep 生产代码 | Stand/Grow/Standpoints` = 0
├─ [L3 数据] 那个词在库里是什么？
│    └─ 机制：写入口只建「整句序列」，不建中间块
│    └─ 证据：节点表里只有 苹/果/是/红/的 + 整句，没有「苹果」
└─ [L4 接口] 「不在库里」怎么表达？
     └─ 机制：用 `0` 当哨兵值 —— 对程序正确，对消费者是空白
     └─ 证据：`{"target":0}` 旁边本该有 `"text":"是红"`
```

### A.4 关键转折

**用户说：「1 维读一个 2 维读一个，到底在读什么？这些数据不是同一个超图吗？」**

这句话逼我去读**最初的原始要求**。翻出一篇标着「已作废」的旧稿，里面有一年前的原话：

> 「维无轴，维就是维，是时空的具象化表现形式，本身就只是一个标签而已，
> 具体内容要看这个标签包含的含义是什么，**长度不是维度**。」
> ⇒ **工具不计算维；工具交还含义，维是读者贴的标签。**

**一句话推翻了整个方向**：不是修数值，是**这个函数不该对外算维**。

### A.5 落地（约 90 行，全是加字段）

| 层 | 改动 |
|---|---|
| L3 | 材料结构加「整段读法 / 前文 / 后文」三个字段 |
| L4 | `target: 0` 时给字；`Via` 加人话解释；截断给 `count + total` |
| L5 | 消费者现在能直接读到「苹果后面是红的」 |

**验收（用户的原话标准）**：
> 「AI 想要了解苹果，回忆出来的内容能够解释苹果这个词的所有词都包含在内。」

实测：
```
忆「苹果」→ 苹果是红的 / 苹果是青的 / 苹果是甜的 / 苹果是酸的 / 青苹果是酸的
```
红、青、甜、酸**全部在里面**。达标。

### A.6 最大的坑：冻结契约

第一版直接加字段 → **一次搞红 9 个测试**。

最快让它变绿的办法是改断言 —— **但那正是这个项目明令禁止的**
（「禁止事后放宽判据」）。

正确做法：**新能力全部走 `?explain=1` 开关，默认形状逐字节不变。**
验证：不带开关时输出与改动前完全一致。

## 案例 B：「问题被压平了」→ 一致性检查的数学天花板

### B.1 用户原话

> 「审计报告把问题找出来了，但是**问题被压平了**，需要深入继续递归研究这个问题，
> 细化出来后才知道到底如何处理。」

### B.2 递归路径

```
【核心问题】为什么 22 个问题的报告仍然「压平」？
├─ [L0] 审计的 7 条检查都在查什么？
│    └─ 全部是：格式 / 指针存在性 / 字符串一致 / 禁用词
│         ⇒ 断言形式都是 `A == B` 或 `matches(形态)`
├─ [L1 数学] `A == B` 能发现什么？
│    └─ 机制：它是**等价关系**。对任意 c，把全体 A、B 同时换成 c，
│         检查输出**完全不变** ⇒ 检测力对「一致地错」恒为零
│    └─ 推论（反直觉）：错误传播 = 复制 = **提高一致性**
│         一个错数被抄到 8 个文件 ⇒ 检查全绿 ⇒ **错得越广越像真的**
├─ [L2 语义] 那 22 个问题真实分布在哪些层？
│    └─ 实测：L1 有 1、L2 有 3、L3 有 6、L4 有 2、L5 有 1、L0 有 9
│         ⇒ 13 个真问题被翻译成 L0 语言才报得出来
└─ [L4/L5] 为什么这两层完全没被检查？
     └─ 机制：这两层的**术语覆盖率是 0%**（一个词都没定义）
          ⇒ 没有词汇就无法提问 ⇒ 不可能有检查条目
          ⇒ 这不是审计不努力，是**范畴缺口在传导**
```

### B.3 三个审计没抓到的东西

| 发现 | 怎么找到的 |
|---|---|
| 一个「全项目最重要结论」的支撑倍数（3700×）**算不出来** | 用同一行的两个 QPS 重算，得 2660× |
| 一个区间（114–205 B/行）**被自家数据打破** | 同一份文档里另有 243.7 B 的记录 |
| 同一个数（1.1s）在一篇里是「实测判据」，在另一篇里是「已作废」 | 交叉搜同一个值 |

**共同点**：都不是「数值错」，是**判据的值域错**。

### B.4 落地：把检查锚到外部事实

写了 7 项检查，**全部锚在代码/算术/运行时**，不锚另一份文档：

| # | 检查 | 抓什么 | 有效性验证 |
|---|---|---|---|
| 1 | 硬事实断言 | 文档数 ≠ 代码 | ✅ 抓到版本号过期 |
| 2 | 指针内容锚 | 指针有效但指错 | ⚠️ 需先补锚点 |
| 3 | must-call | 空循环冒充实现 | ✅ 抓到「测量脚本从没调过被测函数」 |
| 4 | 闭式区间 | 自洽但违反物理界 | ✅ 抓到「每行 32 字节」低于物理地板 |
| 5 | 平移测试 | 检测器有没有牙 | ✅ 注入即红 |
| 6 | 倍数自洽 | 倍数算不出来 | ✅ 抓到 3700×→2660× |
| 7 | 指针内容推断 | 指针指错内容 | ✅ 量出 98 条（真实债） |

**第 4 项是最强的**：一个「全世界只有一处」的自洽错误，
`A==B` 在结构上永远发现不了，**一步算术就杀死**。

### B.5 方法论产出

这一轮之后总结出 8 条原则，其中三条最关键：

1. **删文档测试**：把被检查的文档全删，这条检查还能跑吗？能跑 = 事实检查。
2. **闭式区间**：每个数必须配物理下界（不依赖任何环境）。
3. **平移测试**：一条从没红过的检查，等于没写。

## 两个案例的共同结构

```
用户说症状（L5 感受）
  ↓ 不许直接改代码
还原成一个核心问题 + 解释标准（R0）
  ↓
拆成 N 个问题，每个标认知层（R1）
  ↓ 若全落 L0 ⇒ 还在表面，回去
每个问题挖到机制，并问「前提被谁违反」（R2）
  ↓ 卡住时回去读用户原话
分数据流 / 信息流，问消费者能推出什么（R3）
  ↓
落盘：它是什么、为谁、怎么被下次读懂、坏了怎么定位（R4）
```

**案例 A 的教训**：不要用「加字段」解决「模型接不上」。
**案例 B 的教训**：不要用「多查几条」解决「判据值域错」。
