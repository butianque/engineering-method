# 借口表（压力下的标准回答）

> 用法：**在你准备跳步的那一刻，把理由摊开看。**
> 这份表不劝你，只是把"这个理由"和"事实"并排放。
>
> 扩容规则：每遇到一个新借口，就往表里加一行。**表越长越好用。**

---

## 一、层一·定向（域 / 三定 / 切片表）

| 借口 | 现实 |
|---|---|
| 「这个改动很简单，不用立项」 | 简单的是你看到的那一块；缺的是你没看到的其余六块 |
| 「需求很明确，不用立核」 | 明确的是零件，不是困境。零件清楚不等于链路清楚 |
| 「我先写，边写边想」 | 边写边想出来的结构 = 现状的复述，不是应有的清单 |
| 「先把表列出来，写完再补探针」 | 补的探针一定照着代码写 = 把现状当应有 |
| 「这行写不出探针，先标"存在"吧」 | 写不出探针 = 无法证明存在 = 按 `不存在` 算 |
| 「另一个仓库不用改」 | 你验证过另一个仓库的调用点吗？没验 = 不知道 |
| 「用户没说要这个」 | 用户说的是困境，不是零件。第 4 行（数据）是困境的一部分 |
| 「先做 MVP，其他以后再说」 | MVP 也要 7 行都在。少一行的 MVP 是不可用的 MVP |
| 「这次范围很小」 | 范围小不等于链路短 |
| 「这个字段是给以后留的」 | "以后"没有判据。留了 = 现在就要验它能用 |

---

## 二、层二·施工（每片）

| 借口 | 现实 |
|---|---|
| 「测试都过了」 | 测试只能断言**已写代码**的行为。不存在的东西不产生红色 |
| 「我在脑子里过了一遍」 | 脑内过一遍没有退出码 |
| 「逻辑上是通的」 | 逻辑通不等于链路通。中间还有路由、中间件、序列化、鉴权 |
| 「函数级测过了」 | 函数不知道中间件在前面 |
| 「只改了一行，不用全跑」 | 一行也可能改在契约上。**损伤会在"只改一点"的窗口里累积** |
| 「先改完所有，最后跑一次」 | 集中的"只改不测"会造成不可逆损伤 —— 必须交替（改一处跑一次） |
| 「本地能跑」 | 本地是不是同一个配置、同一个数据、同一个版本？ |
| 「之前都是这么做的」 | 之前也一直在"零散" |

---

## 三、门 4（一片收口）

| 借口 | 现实 |
|---|---|
| 「端到端太慢，跑单测就够了」 | 单测测不到路由和鉴权。**这两处正是最容易坏的** |
| 「只测一个端点就行」 | 漏写的端点不红。只打一个 = 只测了一个 |
| 「状态码 200 就说明好了」 | 200 但数据错，是最难发现的失败 |
| 「失败路径不好测」 | 不好测 ≠ 不测。至少测一条空 body |
| 「这个测试一直是红的，先放着」 | 长期红的测试 = 长期没有约束力，等于删了 |
| 「新测试跑通了」 | 它先红过吗？没红过 = 不知道它有没有约束力 |
| 「手动点了一下，没问题」 | 手动没有记录、不能重跑、别人无法复核 |

---

## 四、撞墙阶段（AI+AI 环路）

| 借口 | 现实 |
|---|---|
| 「探针红了，肯定是探针写错了」 | I4：先问 AI2，拿回依据（文件:行号/命令输出）再改 |
| 「我改一下探针它就绿了」 | 这是**检查器被检查对象修改**。比不检查更坏 |
| 「AI2 说没问题」 | 依据呢？没有文件:行号或命令输出 = 无效回答 |
| 「AI2 说的和我一样，不用问了」 | 说明它没换框架。作废重问 |
| 「再想一遍也许就想通了」 | 无外部反馈的递归批判，信息量衰减 55%（有实验数据） |
| 「换个更强的模型试试」 | 换的是映射，不换定义域。不动点还是那个点 |
| 「多叫几个 AI 投票」 | 同一个 span 的重复采样。投票会选出"共识的错误" |
| 「AI2 也搞不定，算了」 | 标 `degraded` 报警，交给人工出口。**不许静默放弃** |

## 五、声称完成时

| 借口 | 现实 |
|---|---|
| 「基本完成」 | 基本 = 有行还是 `不存在` |
| 「完成度 90%」 | 这个数字从哪来？没有来源 = 编的 |
| 「剩下的是小问题」 | 小问题的定义是什么？能量化吗 |
| 「功能已经实现了」 | 实现了 ≠ 接上了 ≠ 能用了。三件事 |
| 「后面再优化」 | 优化和缺失是两件事。缺的不是优化项 |
| 「代码写完了」 | 代码写完只是第 2 行（业务函数） |

**称完成时必须能答：**

```
集成面 N 行：存在 M、新建 K、不存在 0
验收退出码 0，日志在 .runs/acceptance.log
```

**答不出这两行 = 不许说完成。**

---

## 六、Red Flags（看到自己在说这些，立刻停）

- 「应该」「可能」「大概」「通常」「我记得」
- 「我看了一下，没问题」
- 「这里逻辑上是通的」
- 「先这样，后面再补」
- 「差不多就行了」
- 「这次特殊情况」

**处置**：停下，去跑一条命令。
**跑不出命令，就把那一行标成 `不存在`。**

---

## 七、违规后的处置（不是"下次注意"）

| 违规 | 处置 |
|---|---|
| 没立项就写业务代码 | 代码**不算数**，先补表，再重做 |
| 表里有"不存在"却声称完成 | 该次"完成"**作废** |
| 验收没跑就报"好了" | 该声明**作废**，跑完再报 |
| 自己改了探针让它变绿 | 该轮**作废**，问过 AI2 再来 |
| 判据在结果出来后才定义 | 判据被视为**已污染**，作废 |
| 同一问题失败 ≥3 轮 | **停止改代码，质疑架构** |
| 在"猜"的地方没去查 | 该结论标记为**推测**，不许当事实写进文档 |

---

## 八、诚实边界（这一条不许删）

**这个 skill 覆盖"会报错的缺失"。**
**覆盖不了：不报错但结果错的、连"错了"都不知道的。**

**⇒ 所以不许说"全都没有问题"。**
**正确说法**：「按 7 行骨架无缺口；骨架之外未覆盖。」

**说"全都没问题"的人，一定没跑过 gate。**
