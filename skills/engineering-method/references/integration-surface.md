# 集成面表：怎么列全，怎么判必需

> 这是整个 skill 唯一的原创部分。读完这一份，你应该能对**任何**改动列出它的集成面。

---

## 一、7 行骨架从哪来

它不是拍脑袋想的，是从"一条真实链路要跑通，必须同时成立什么"反推的。

```
请求进来 → 谁接？（入口）
        → 哪段代码干活？（业务函数）
        → 谁在调它？（接线）
        → 数据从哪来、存哪？（数据）
        → 出错怎么往回传？（失败路径）
        → 谁有权限、读哪个配置、能并发几个？（配置/权限/并发）
        → 坏了怎么知道、怎么退？（可观测/可回滚）
```

**7 个问号，缺一个链路就不完整。**

**AI 的默认行为是只做第 2 个**，然后报告"功能已实现"。
**这就是"零散"的物理成因。**

## 二、一个真实案例（用来校准你的判断）

**任务**：修"面板一直在操作也被踢下线"。

**AI 只改第 1 处时的真实结果：**

```
改动：sessions.go 里 IP 绑定默认值 true → false
测试：go test ./internal/api/handlers/management/  →  ok  20.3s
结论：全绿
实际：用户仍然被踢
```

**为什么**：真正的修复要 **9 处、跨 2 个仓库**：

| # | 要素 | 位置 |
|---|---|---|
| 1 | 后端 IP 绑定默认值 | `sessions.go` |
| 2 | 后端 401 原因码 | `sessions.go` |
| 3 | 中间件语义 | `handler.go` |
| 4 | 换密钥路径 | `config_basic.go` |
| 5 | v8 配置路径 | `config_v8.go` |
| 6 | 面板 401 世代校验 | `client.ts` |
| 7 | 面板续期分流 | `session.ts` |
| 8 | 面板空闲守卫 | `SessionIdleGuard.tsx` |
| 9 | 面板 0 值语义 | `useAuthStore.ts` |

**⇒ Go 测试一条也扫不到第 6–9 处，因为它们在另一个仓库。**

**⇒ 这 9 行不是 AI 想出来的，是"跨仓库改动"这个模式的预置行。**
**这就是为什么骨架必须固定：预置的行不会因为"没想到"而消失。**

## 三、接缝提取：怎么给**没见过**的改动列行

**骨架管通用，接缝管具体。**

**接缝 = diff 触碰到的"对外承诺"。** 从 diff 上直接读，不需要语义判断。

| diff 里的东西 | 它制造的接缝 | 该查什么 |
|---|---|---|
| 函数签名（新增/改返回值） | 所有调用点 | `grep -rn "funcName(" .` |
| 路由（新增/改路径） | 所有调用方 | 客户端代码、nginx、其他服务 |
| 字段（新增/改名/删） | 所有读写点 | `grep -rn "fieldName" .` |
| 配置项（新增） | 所有读取点 | `grep -rn "configKey" .` |
| 表结构 | 迁移、旧数据、索引 | 迁移脚本、回滚脚本 |
| 错误码/文案 | 前端映射、监控告警 | 前端、告警规则 |

**关键：接缝是结构事实，不是语义判断。**
**所以它能给出你"没想到"的行 —— 因为它从 diff 读，不从你的范畴读。**

## 四、悬置审计：怎么判某一项是不是真的必需

**做法**：假设它不存在 → 跑链路 → 看断不断。

| 结果 | 判决 | 处理 |
|---|---|---|
| 断（编译失败 / 500 / 超时 / 数据丢失） | **承重** | 保留，优先级最高 |
| 不断 | **装饰** | 降级为可选 |
| 拿掉之后更好 | **干扰** | 删掉 |

**为什么这比"我觉得需要"强**：**它有退出码。**

**先拆哪个**：越是被多处引用的越先拆（约束密度高 = 承重墙）。
先拆承重墙最能暴露问题。

**⚠️ 必须隔离环境跑。** 这是硬约束 —— 悬置审计会故意弄坏东西。

## 五、探针的三种写法

### ① grep 型（结构存在性）

```bash
grep -rq "EnsureSequence" internal/store/ && exit 0 || exit 1
```

**适合**：检查函数/字段/配置是否存在。

### ② 命令型（能跑通）

```bash
curl -sf -o /dev/null http://localhost:8080/health
```

**适合**：检查入口是否活着。

### ③ 断言型（行为正确）

```bash
[ "$(curl -s -o /dev/null -w '%{http_code}' -X POST "$BASE/api/x" -d '{}')" = "400" ]
```

**适合**：检查失败路径。

**三条纪律**：

```
P1  必须是命令，不是"人工判断"
P2  必须 5 秒内跑完
P3  必须只读 —— 探针不许改数据
```

**写不出探针怎么办**：标 `不存在`。
**写不出 = 无法证明存在 = 按不存在算。** 这条没有例外。

## 六、常见错误

| 错误 | 为什么错 | 正确做法 |
|---|---|---|
| 表格行由 AI 自由增删 | 它会把没想到的行删掉，报告全绿 | 骨架固定 7 行，只增不改 |
| 探针写成"人工确认" | 人不在回路里就没法跑 | 必须是一条命令 |
| 状态写"部分完成" | 三值之外的值无法判定 | 只有 `存在` / `本次新建` / `不存在` |
| 先写代码再补表 | 补的表照抄现状，等于把现状当应有 | 先表后码 |
| 只列本仓库 | 跨仓库的接缝是盲区 | 接缝提取（第三节） |
