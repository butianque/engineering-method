# P1 — 分解与逐级判定

> 本阶段的存在理由：**一个没写判据的分解，只是把问题换个说法。**
> 现成的 MECE / issue tree 类 skill 都能"分解"，但止于"标注需要什么证据才能关闭分支"；
> 它**不给逐级判决**。本阶段补的就是那一格。

## 1. 树的形状

```text
C                       ← 核心问题（一句话，可回答）
├── C.1                 ← 一级子问题
│   ├── C.1.1
│   └── C.1.2
└── C.2
    └── C.2.1
```

规则：**1 个核心 + N 个子问题；每层可再分，直到每个节点"可执行、可验证"。**

## 2. 节点 schema（缺任一必填项 → 整树不通过）

| 字段 | 含义 | 缺了会怎样 |
|---|---|---|
| `id` | 层级编号，如 `C.1.2` | 无法被后续阶段引用 → 不许进 P2 |
| `question` | 可回答的一句话；**禁用"应该 / 可能 / 大概"** | 退回重写 |
| `parent` | 父节点 id；根节点为核心问题 | — |
| `load_bearing` | 是否**承重**：它为假会不会否掉某个候选方案 | 未标注 → 默认承重，从严 |
| `criterion` | **判定它真 / 假的判据**：一条命令、一个断言或一项证明义务 | **缺 → 整树不通过** |
| `evidence_provenance` | `tool-observed` / `user-reported` / `document-reported` / `experimentally observed` / `measurement-derived` | 未标注 → 不许把"用户说的"当"已证实" |
| `verdict` | `SUPPORTED` / `REFUTED` / `UNRESOLVED` / `OUTSIDE_FRAME` | — |
| `close_evidence` | 关闭本节点还差什么证据 | — |

> `evidence_provenance` 的用途：**永远不要把 user-reported 升格成 independently verified**。
> 同一条事实，来源不同，可信度不同，判决时必须区分。

## 3. 逐级判定规则（本阶段的核心，现成 skill 都没有）

**父子一致性（硬规则）**

```
父节点 SUPPORTED  ⇔  其【全部承重子节点】均为 SUPPORTED
任一承重子节点 REFUTED  →  父节点必须 REFUTED 或 REFORMULATE
```

- **不许"局部成立就算成立"。** 只要有一个承重子被推翻，整条链的结论必须跟着改。
- 非承重子节点被推翻 → 父节点保持原判决，但必须在树上留痕。

**MECE 自检（跑之前先做）**

- **无重叠**：同级分支不能有两个在回答同一件事（同义说法要合并）；
- **无缺口**：同级分支合起来要覆盖父问题（漏掉的可能性要补节点）；
- 自检不过 → **先修树，再跑实验**。树是错的，实验只会证明一个错的东西。

**判决词表（封闭，不许自造）**

| 判决 | 含义 | 下一步 |
|---|---|---|
| `SUPPORTED` | 判据跑出来了，支持该命题 | 可继续 |
| `REFUTED` | 判据跑出来了，推翻该命题 | 按父子规则向上传导 |
| `UNRESOLVED` | 判别不了（证据不足 / 不可判别） | 换判别点重做，**不许宣称成立** |
| `OUTSIDE_FRAME` | 结果落在框架外（候选集可能不全） | **保留残差**，不许塞给最近的候选 |

> `UNRESOLVED` 与"没跑"是两回事。**跑都没跑就写 UNRESOLVED 是违规。**

## 4. 什么时候该往下分、什么时候该停

- **往下分**：当前节点无法直接给判据（"它太大了，测不了"）。
- **停下**：该节点已有可执行判据、且能跑出 SUPPORTED / REFUTED。**再分就是噪声。**
- **不许**为了"看起来完整"把树铺满；每个节点都要能在 P2 里指认到落点，否则删掉。

## 5. 与其它阶段的接口

- **进**：P0 冻结的 Question 就是 `C`。
- **出**：树的**叶子**就是 P2 绑定表里 `req_id` 的来源；带判据的叶子直接进 P3 当判别检验。
- **回**：P3/P4 跑出 `REFUTED` 或 `OUTSIDE_FRAME` → 回到本阶段改树（**不是改判据**）。

## 6. 反例（这些写法一律不算分解）

| 写法 | 为什么不算 |
|---|---|
| "分析一下性能问题" | 不可回答，没判据 |
| "优化数据库" | 是方案不是问题（把 solution 当 question） |
| 只列 3 个方向但没有承重标注 | 无法判断哪个被推翻会否掉结论 |
| 每个分支都写"需要更多数据" | 这是"标注证据"不是"判定" |
| 树深 5 层但叶子没有判据 | 铺满 ≠ 分解 |
