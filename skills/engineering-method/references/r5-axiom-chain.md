# R5 认知链：从一句原话，到一条可复算的规则

> **这一份解决的是**：为什么照着用户说的做完，用户会说「没有这层认知，皆是做出来的又是四不像」。
>
> **一句话**：**四不像 = 拿到了结论，没拿到生成结论的那个东西。**

---

## 1 病灶：抄结论，不抄前提

真实对话（DSJY，原话）：

```
用户：超边=节点。
AI  ：记下了 ⇒ 实现「去重」。
用户：你要搞清楚，去重是因为（超边=节点）。已有节点的情况下，只建超边集。
      不需要去重，即使入图了也会因为重复的原因，该节点只会新增一条关系。
      没有这层认知，皆是做出来的又是四不像的东西。
```

**同一句话，两条路**：

| 路 | 拿到什么 | 交出来的东西 |
|---|---|---|
| 抄结论 | 「要做去重」 | 一个 `dedupe()` 函数 + 一张去重表 ⇒ 多余、会与同一性打架 |
| 抄前提 | 「超边是节点 ⇒ 同一性免费」 | 不需要 `dedupe()`；表里只有 `kind`；判据是「同一段再写一次，增量 0」 |

**⇒ 判据：每条工程规则，都要能回答「它是从上一条哪句话推出来的」。答不出，它就是四不像的零件。**

## 2 三种认知失败（按危害排序）

| 失败 | 长什么样 | 用户会怎么说 | 修法 |
|---|---|---|---|
| **改写** | 把用户的原话翻译成「更专业」的说法 | 「不要写这种东西，有个屁用」 | 原话账本（§5） |
| **压平** | 把有区别的词合成一个 | 「宽、层、深度、维、步数，到底是哪个」 | 同形词分离（§4.3） |
| **无公理** | 抄结论不抄前提，规则各自都「对」 | 「矛盾，全部拉出来逐行比对」 | 公理链（§3） |

**这三种都不产生红色测试。** 它们产生的是一份「看起来完整、做出来不对」的东西。

## 3 公理链：四步，一步不许跳

```
① 锚   用户原话，逐字，带出处              → 账本一行
② 拆   不可再推的那一句（公理：A = B / 只有 N 种）
③ 推   由公理必然得出的结论，一步一条，写「因此」
④ 落   条文 / 工程规则 + 一条可复算判据
```

### 3.1 走一遍（真实链条）

```
① 锚   「超图内，维度的节点/超边都是符号；{}是超边集，[]是节点；超边=节点」
② 拆   公理 A1：一条超边本身是一个节点。
③ 推   因此 同一成员序列 = 同一个节点（同一性由结构给出，不靠额外判定）
       因此 不需要「去重」这个动作，只需要「已存在则复用」
       因此 表里 {} 与 [] 同表，只用 kind 区分，不存在第二种实体
④ 落   工程规则：intern_edge 命中即复用；不留 dedupe()
       判据：同一段写两次，entities/memberships 增量 0，edgeId 相同
```

### 3.2 拆不出来的症状

- 同一条规则在两份文档里说法不同 ⇒ 它没有公理，只有各自的理由。
- 一个函数需要「特判」才能与另一处一致 ⇒ 公理没落成唯一权威。
- 加一个新功能要改 N 个 switch ⇒ 公理被写成了枚举，不是结构。

**⇒ 公理链的产出物不是文字，是「唯一权威」。同一个概念只允许一处定义（见 `r6-project-charter.md` §3）。**

## 4 四把尺：每个词、每个分类、每条规则都要过

### 4.1 反例列（词的牙齿）

**格式固定三列：称呼 / 定义 / 反例（不是这个）。**

| 称呼 | 定义 | 反例 |
|---|---|---|
| 符号 | 一个字素簇，NFC 归一后的字符串 | 一个码点（`é` 与 `e`+U+0301 是同一符号）；一个词 |
| 宽 | 一个块含几个符号 | 深度；层 |
| 深度 | 嵌套层数 | 宽；注意链的步数 |

**判据：写不出反例的词，说明它还没被定义，只是被命名了。**
**⇒ 没有反例列，就没有「边界」；没有边界，「像」就能当「是」。**

### 4.2 穷举（分类的牙齿）

用户的原话式提问：**「1 / 2 / 混合 是穷举的，这里有吗？」**

分类必须回答三个问题：

```
1. 为什么只有这几种？（给出生成方式，不是举例）
2. 第 N+1 种会落在哪一类？（必须能答，答不出说明有漏）
3. 每一类在库里有没有实体？（文档里有、库里没有 = 名词，不是结构）
```

**判据：说不出「为什么只有这几种」的分类，不算范畴，只是举例。**

### 4.3 同形词分离（一词多义的裂开）

真实案例：一个「深度」同时指了四件事。

| 被粘住的词 | 实际是 | 谁决定 | 判据 |
|---|---|---|---|
| 宽 | 块含几个符号 | 一次切片 | `n(n+1)/2` |
| 层 | 第几次组合（宽 = 层 + 1） | 切片轮次 | 层 = 宽 − 1 |
| 深度 | 嵌套层数 | 成员里有没有「集」 | 深度 = 1 + max(成员深度) |
| 步数 | 注意链走了几步 | 注意力展开 | 步数 ≠ 深度 |

**操作：把候选词全列出来，两两问「能不能互换」；不能互换就裂成两列，各给定义与反例。**
**⇒ 裂开之后，条文里只允许一个词指一个量；改名要改到标识符（中文词 → 英文标识符一对一）。**

### 4.4 不需要清单

**范畴的物理形态不只有「不做功能」，还有「不用工具」。**

```
数学：用到 集合与映射 / 区间 / 等价类 / 组合计数 / 闭包 / 不动点
      不需要 向量空间 / 概率 / 微积分 / 图神经网络
依赖：不需要 第二种语义、第二套 API、第二个真相源
```

**判据：每一类「不需要」都要写「用什么替代」。没有替代的排除，等于没排除。**

### 4.5 判据先于选型

**顺序不许反：先立判据，再对照候选，最后才允许说「选它」。**

真实对照（语言选型）：

```
LG1 能表达代数数据类型（原子/块/区间/混合/切分）
LG2 无 GC 停顿        LG3 Unicode 一等支持
LG4 存储驱动成熟      LG5 单写多读      LG6 编译期检查

→ 三候选逐条打勾 → 选择 + 代价（开发慢、借用检查 → 用 u32 句柄规避）
```

**判据：选择理由里不许出现「我觉得」「生态好」「熟悉」。理由必须指回某条判据。**

## 5 原话账本（user-quote ledger）

**为什么要账本**：用户的原话是**唯一权威**。AI 一转述，权威就变成了 AI 的理解。

**格式**：

| # | 原话（逐字，不改标点） | 出处 | 它立了什么 | 落到哪条条文 |
|---:|---|---|---|---|
| 1 | 超边=节点 | 用户 11-17 23:43 | 公理 A1 | `10-范畴表` §1.1、`30` §2 |

**四条硬规**：

```
Q1 逐字。不许「概括为」「本质上是」。改一个字就不是他的原话了。
Q2 用户已给的表述 = 权威原文。只许三种动作：对齐 / 补充 / 指出矛盾。
Q3 矛盾处理：把所有相关原话拉出来逐行比对，裁决哪一句作废。
   不许「综合一下」——综合就是压平，两句话都会活下来。
Q4 用户说「不要写这种东西」= 形态被驳回，不是内容被驳回。
   改形态（条文制 / 编号制 / 表格），不是加解释。
```

**Q3 的反面教材**（真实）：

```
AI 交出一份「§0 先回答一个问题…一个块宽…一个块深度…注意链一步…」的分析稿
用户：不要写这种东西，有个屁用。  ← 形态错：他在要条文，AI 在写论文
```

**⇒ 形态判据：用户的系统若已被他写成编号条文，你的产出也必须是编号条文，逐条对齐，不许另起文体。**
