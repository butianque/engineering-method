# R6 立项：立项书是标准，不是文档

> **这一份解决的是**：立项书写完，项目还是越做越散；几十个文档各自解释，互相不解释。
>
> **一句话**：**立项书不是给人看的介绍，是给后面每一次比对用的判据来源。**

---

## 0 为什么「立项即标准」

用户的原话：**「回到原来的立项即标准」**、**「以我当前的话为基准，将矛盾的原话全部拉出来逐行比对」**。

两句合起来是一个定义：

```
立项书  = 基准（基准不是摘要，是能被逐行比对的那一份）
下游文档 = 必须能被基准逐行判「是 / 否」的声明
```

**写成「项目介绍」的立项书，判不了任何东西**，于是后面出现：

```
讨论 → 写文档 → 再讨论 → 又写一篇 → 两篇说法不同 → 谁对？
```

**⇒ 立项的产出不是一个文档，是四样东西：基准（7 段）＋ 域划分（9 域）＋ 纪律（宪法）＋ 状态（一版一张表）。**

---

## 1 立项书七段（缺一段，后面必有一条失控）

| # | 段 | 内容 | 判据 |
|---:|---|---|---|
| 1 | **一句话** | 系统是什么，一句话说完，含最强的那条约束 | 去掉「不判断/不做语义」这类约束，句子会变成另一个系统 |
| 2 | **本版目标** | ≤3 条，每条带**完成证据** | 每条能指到一个命令、一次构建、一份计数 |
| 3 | **域表** | 域 / 回答什么 / 入口文档 / 现状 | 每个域只有一个入口；入口文件真实存在 |
| 4 | **依赖顺序** | 串（谁依赖谁）/ 并（可并行）/ 汇（谁等全部） | 串链上不许反向依赖（反向依赖 = 环形 = 谁也改不了） |
| 5 | **落位表** | 文档与代码分家；新文件能映射到某一行 | 一个文件只属一个域；代码目录里不放文档 |
| 6 | **不做** | ≥5 条本版边界 | 每条能让一个提议当场出局 |
| 7 | **裁决点** | 已定 / 未定；未定写「它决定哪些下游文档的写法」 | 未定项不阻塞前面，但必须有归属 |

**第 2 段的写法**（真实形态）：

```
GOAL1 设计冻结：九个域各一份文档，条文与判据齐，互相不打架。   ← 证据：14 份文档、九域全有入口
GOAL2 最小可跑：记/忆/感 三个动作，在单人库上过全部判据。      ← 未开始
GOAL3 形式化：三条主命题 + 深度 + 闭包 + 切分 + 锚点。        ← 证据：38 定理、0 sorry
```

**⇒ 「未开始」是合法的目标状态；含糊才是非法的。**

## 2 九域：少一个域，就有一类问题没有词汇

| # | 域 | 回答什么 | 错过的症状 |
|---:|---|---|---|
| 1 | **数学 / 认知范畴** | 词怎么定、边界在哪、什么不属于本系统；要用哪几件数学；语言怎么选 | 一义多名、名实不符；选型靠喜好 |
| 2 | **架构** | 系统长什么样、谁调谁、库外那层在哪 | 删一层，其余层症状不可预测 |
| 3 | **形式化证明** | 哪些命题被机器证过、哪些只靠人读 | 「我认为成立」混进判据 |
| 4 | **工程 \ 架构** | 代码怎么分层、依赖方向、换库动哪里 | 核心 import 存储；换库要改全仓 |
| 5 | **框架** | 模块、接口、目录、装配点 | 模块职责互相渗透；装配顺序靠运气 |
| 6 | **工程片段细则** | 事务 / 锁 / 幂等 / 编码 / 测试的具体写法 | 同一件事三处写法不同 |
| 7 | **数据流 \ API** | 字节怎么变成行；端点参数 / 响应 / 错误码 | 数据流有了，信息流没人管 |
| 8 | **消费者 / 信息流** | 谁在用、时机、频率、方式、失败怎么办 | 能力都在，从没接出去 |
| 9 | **工程判据** | 怎么算过；红一条不许合 | 「测试绿了」= 完成 |

**每域必须交三件套**（空一项，该域等于没建）：

```
回答什么  一句话，写不出说明域没划清
交付什么  具体到文件：表 / 图 / 清单 / 定理表 / 判据表
判据      该域「怎么算过」；尽量一条命令，退而求其次一条检查
```

**裁剪规则**：
- 只许把「本版不做」的域写进 §1 第 6 段然后不建文档；
- **不许把两个域并成一个文档**（合并 = 该域失去入口 = 那类问题再也看不见，见 `r1-cognitive-layers.md` §5「没有词汇就无法提问」）。

## 3 文档宪法（六条 + 两张表）

**为什么需要**：九域是串联 + 并联，一处改了另处没改，下游全错，而**测试测不出来**——不存在的东西不产生红色。

### 3.1 六条硬规

| # | 规 | 禁止 | 要求 |
|---:|---|---|---|
| **D1** | 只写当前真相 | 修订记录、补记、「原写…现改为…」、变更日志段 | 把旧句子**直接替换**成新句子；历史留在 git |
| **D2** | 插入 / 替换 / 删除，三选一 | 追加到文件末尾当「补充说明」 | 插入到它应在的位置，不改别的节号 |
| **D3** | 一个概念只有一处 | 同一概念在两份文档各定义一次 | 其余处只引用，不复述 |
| **D4** | 文件数只减不增 | 为「补充」新建文档 | 新增须有它**独占的概念**，否则并进已有文件 |
| **D5** | 编号不复用、不递增 | 删除后让后来者补位 | 前缀一经分配永不给别的域；删除留空 |
| **D6** | 完成改状态，不重读 | 让下一个 agent 从头读一遍已完成文档 | 只改状态表一行 + 证据指针 |

**D1 的判据**：`grep -nE '修订|补记|追加|原写.{0,20}现改为' docs/**/*.md` 必须 0 命中。
**D6 的判据**：状态为「完成」的文档，正文不再出现在任何「先读这些」的清单里。

### 3.2 前缀表（编号不复用的落地）

```
两位大写前缀，全域唯一，前缀 → 域 → 含义 → 权威文件 §节号
CX 称呼  MT 数学工具  IV 不变量  LG 语言判据
AR 架构判据  T 定理  OP 未形式化项
EA 工程架构判据  MD 模块  FM 框架判据
ER 细则条目  TS 测试层级
DF 数据流判据  WP 写路径步骤  RP 读路径步骤  AP 端点判据  EC 错误码
CS 消费者  CI 消费者判据  EE 端到端判据
LN/UT/ST/NM/UV/RD 判据 / 单元 / 结构 / 数字 / 未验证 / 红线
```

**判据：每个前缀只出现在一个文件里。**（`grep -l 'WP[0-9]' docs/**/*.md` 只能命中权威文件）

### 3.3 唯一权威表（一个概念一处）

| 概念 | 唯一权威（文件 §节） |
|---|---|
| 词的称呼 / 不变量 / 语言判据 | `10-范畴表` §1 / §3.2 / §4.1 |
| 写路径步骤 / 表结构 / 物化触发 / 读路径 | `30-数据流与存储` §1 / §2 / §4.1 / §5 |
| 端点 / 错误码 | `31-API接口` |
| 模块 / 装配顺序 | `22-框架与模块` §1 / §3 |
| 定理 / 开放项 | `12-Lean4-形式化` §2 / §4.2 |
| 判据汇总 | `50-工程判据`（只引用，不新造） |

**规则：任何文档写到这些概念，只许写「见 X §Y」，不许复述定义。**复述 = 第二权威 = 下次必然不同步。

### 3.4 可 grep 的纪律判据（NR1–NR9）

```
NR1 不存在裸写的旧编号（A1/E1/G1/L1/M1/U1/V1/I1/D1/H1）
NR2 每个前缀只出现在一个文件
NR3 每个概念的定义句全仓 1 处
NR4 写路径只在数据流文档定义；读路径只在它自己那节定义
NR5 不变量只在范畴表定义
NR6 判据汇总只引用，不新造编号
NR7 正文不含修订 / 补记 / 追加 / 「原写…现改为」
NR8 文件数不增长（新增须先删旧的，或证明独占概念）
NR9 完成状态只在状态表改一行
```

**⇒ 这九条能写成脚本；写不成的纪律，等于没有纪律。**

## 4 裁决点：把「还没定」变成结构

**未定不是缺陷，含糊才是。**

```
已定：语言与分层 = Rust 核心 + TS 只做消费者与循环 + JS/HTML 只做可视化（Go 退场）
      依据：LG1–LG6 逐条对照，不按喜好
未定：工程选择（全连续块 / 全切分 / 惰性物化 / 惰性+按需）
      —— 选哪个，决定「数据流与 API」的写法与「工程判据」的数字
```

**要求**：
1. 每条未定项写**它决定哪些下游文档**；这样它不阻塞前面，也不会被忘掉。
2. 已定项写**依据**（判据编号），不写「综合考虑」。
3. 裁决点只增不删；作废的写「已作废，由 X 取代」（这条是 D1 的例外：裁决史要留）。

## 5 状态表：让「已完成」不再被重读

```
| 文档 | 状态 | 证据指针 |
| 10-范畴表 | 定稿 | 自检 8/8 |
| 22-框架 | 定稿 | doc-reconcile 退出码 0（77 pub 双向一致） |
```

**规则**：
- 接手先读状态表；状态「定稿」的只读它一行，不读正文。
- 状态只有三值：`草案` / `定稿` / `作废`。
- 「定稿」必须有证据指针；没有证据的「定稿」按草案算。

**为什么值得单列一段**：用户的原话是「已经完成的任务，却又要重新读一遍这种问题，浪费时间还浪费资源」。这句话的修法不是「让 AI 更勤快」，是**给完成状态一个可读的位置**。

## 6 立项驳回信号（用户说这句话时，改什么）

| 用户说 | 意思是 | 你该改的 |
|---|---|---|
| 「不要写这种东西，有个屁用」 | **形态**错：你在写分析，他要条文 | 换成编号条文 / 表格；删掉解释性散文 |
| 「我看看是不是这样的」 | 要做**可判的对照** | 每条给「是 / 否」判据，别给叙述 |
| 「你得先规划再去做」 | **顺序**错 | 先出域表 + 依赖序 + 落位，再动手 |
| 「回到立项即标准」 | 它是**判据来源** | 下游每篇都要能被它逐行判 |
| 「各自解释，不是互相解释」 | **耦合**错 | 串链上的文档只依赖前一环；缺口写进依赖序图 |
| 「不完整，X 是穷举的，这里有吗」 | **范畴**没闭合 | 补穷尽性 + 库里实体对照（见 `r5-axiom-chain.md` §4.2） |
