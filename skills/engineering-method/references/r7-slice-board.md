# R7 切片与派活：一次只开一片，每片必须走到两头

> **这一份解决的是**：把整个系统一次性丢给 AI（或一群子代理），收回一堆「测试全绿」，但数据流没走通、信息流交不出东西。
>
> **一句话**：**一片 = 一条能从输入走到行、再从行走回语义的功能；走不到两头的，不是一片，是半片。**

---

## 1 切片表：先有表，再有人

**列固定四列**（少一列就会有人问「这片算完了吗」）：

| 片 | 功能 | 数据流出口（写到哪张表/哪几行） | 信息流出口（消费者拿到什么） | 依赖 |
|---|---|---|---|---|
| F1 | 记 + 读回 | `entities` / `memberships` / `experiences` / `writes` | `nodes` 与 `read(edge)` | — |
| F2 | 忆 | 只读，零新增 | 命中 + 落点（区间 / 两端余量） | F1 |
| F3 | 感 | 只读 | 三向关系全集 | F1 |
| F4 | 锚点 | `anchors` 行 | `alive` / `family` | F1 |
| F5 | 走 | 只读 | 链与落点序列 | F3 |
| F6 | 觉 | 只读 | 同槽 / 共识分组 | F2 |
| F7 | 物化 | 仅被引用时新增 `entities`/`memberships` | 区间可指认 | F1 |
| F8 | 重启 + 幂等压力 | 全量读回 | 逐字节相同 | F1–F7 |
| R1…Rn | 重构 | 无（行为不变） | 公开面收敛 / 响应字节不变 | 前一片 |

**顺序写成一行，让人一眼能排**：

```
F1 → (F2 ∥ F3 ∥ F4) → (F5 ∥ F6) → F7 → F8 → R1 → R2 → …
```

**三条规则**：

```
S1 竖切，不横切。禁止「先把所有模块的骨架写完，最后接通」——那让每一步都不可验。
S2 重构片也进表，且必须标「行为不变」；测试条数改前改后必须相等（或解释差在哪）。
S3 一片只碰一个写域；跨写域 = 拆片，不是加权限。
```

## 2 每片的四问（规划一片的时候就要答完）

```
① 数据流怎么走？   输入 → 归一 → 切分 → 落符号 → 写边 → 写锚点 → 物化 → 一个事务
② 信息流怎么回？   读库 → 建图 → 读回 → 落点 → 交还（消费方能推出什么）
③ 落在哪个文件？   具体到 src/xxx.rs 的函数名；新文件要映射到落位表某一行
④ 怎么算过？       每条判据 + 每条判据的反证（注入什么，必须红）
```

**②是最常被跳过的一问。** 只答①的症状：接口返回一堆 id，消费者推不出任何东西。

### 2.1 两个流的观察点（必须写在片里，不许写在脑子里）

| 流 | 观察什么 | 在哪看 |
|---|---|---|
| 数据流 | 字节 → 符号 → 行 | **直接查库**：表、行数、`pos`、事务边界 |
| 信息流 | 行 → 读法 → 落点 → 交还 | 读回字符串、落点区间、两端余量 |

### 2.2 反套壳判据（每片都查）

```
删掉 memberships 里某条边的成员行 ⇒ 该边读回必须变短或失败
若仍然读回原串 ⇒ 读法是被存的、或查表硬拼的 ⇒ 判不通过
```

**为什么这条必须有**：套壳、查表、硬编码都能让测试变绿，只有「删掉成因，看语义崩不崩」测不出来。

## 3 任务书九段（派给子代理的唯一形态）

**一段都不能省**；省哪段，子代理就在哪段自由发挥。

| # | 段 | 写什么 | 为什么 |
|---:|---|---|---|
| 1 | **环境** | 仓库根、命令、工具链钉在哪 | 免得它自己找、自己换 |
| 2 | **先读规范** | 唯一权威文档 + **节号** | 不许它「参考一下」多份文档 |
| 3 | **写域** | 只许改这些 / 不许改这些（含「别碰别的 crate」） | 冲突与越界的第一道闸 |
| 4 | **冻结契约** | 签名、字段顺序、常量，原样贴出 | 它改签名 = 全仓返工 |
| 5 | **语义** | 逐条编号 A1…An / S1…Sn，**每条一句，可判** | 编号是验收的抓手 |
| 6 | **测试** | 每条语义一个测试，编号对齐；不许 `#[ignore]` | 「测了」不等于「按语义测了」 |
| 7 | **反证** | 注入 a/b/c 分别必须红 → 还原 → 全绿 | 证明测试**能失败** |
| 8 | **禁止** | `todo!` / `unimplemented!` / 硬编码期望 / 吞错误 / 改 schema | 把「偷懒路径」逐条堵死 |
| 9 | **交付报告必含** | 测试末 20 行 / 实现位置 + 关键 N 行 / 三处红点 / 实际 JSON 打印 | 报告形态固定，验收才可复用 |

**外加两个字段**：

```
blocked_by: [task-xx]        依赖没完成，不许 claim（依赖序落到任务板，不靠记忆）
write_scopes: [路径…]        机器可校验的写域；报告与 diff 都按它核
```

### 3.1 语义段怎么写（正面样板）

```
A1 一次即活：只带一次 from=X 写一条，alive(X) == true，family(X) 恰好 1 条
A2 无阈值：不要「两次才算活」；一次就够
A3 锚点不是成员：该经历的 members 里不得出现 X（除非正文本身含它）
A9 from = 0 拒绝：不得静默成功
```

**判据：每条语义都能写成一行断言；写不成一行的，说明它还没想清。**

### 3.2 反证段怎么写（正面样板）

```
注入 (a) 让 add_anchor 不去重 ⇒ A6 必须红
注入 (b) 让 alive 恒 true   ⇒ A12 必须红
注入 (c) 删掉存在性校验     ⇒ A7 必须红
三处都要「注入 → 红 → 还原 → 全绿」，并报告红在哪条
```

**为什么反证不能省**：没有反证的测试 = 一条永远为真的断言。子代理会「让测试通过」，不会「让测试能失败」——除非你要求它还你一个红色。

## 4 lead 的三件事（不许全交出去）

```
L1 先写冻结骨架     签名 / trait / schema / 目录 / 常量，自己写，子代理只填函数体
L2 自己写验收探针   独立于子代理的测试（放在自己的写域里），用来验「它说的」和「真的」一致
L3 逐条验收          不信「全绿」，只信三样：语义是否属实 / 是否套壳 / 是否查表
```

**L2 的真实形态**：主代理建 `crates/app/tests/r3_interval.rs` 这类**验收探针**，跑出 4 条独立断言；
子代理报告的基线是 276，探针 4 条使 272 ≠ 276 的差异立刻可见（而不是被「测试全绿」盖住）。

**L3 的三问（对每份交付报告）**：

```
1 它贴的测试输出，是不是它自己写的那条测试跑的？（不是「workspace 全绿」）
2 它说「0 处要改」时，有没有把 12 条语义逐条变成可失败的测试压上去？
3 它新增的字段/键/分支，是不是我冻结契约里允许的？（多一个键 = 套壳的开始）
```

**⇒ 报告里最该看的不是「通过」，是「我改了几处、原写法 → 新写法 → 为什么」。**

## 5 开发日志（每片收尾，不是每版收尾）

```
<版本>/开发日志/<时间戳>-<名称>.md
```

**六项固定**：

```
1 改了什么（文件 + 函数）
2 得出了什么（新事实 / 被推翻的假设）
3 架构上有什么变化（依赖方向、模块边界）
4 加了哪些文件（要能映射到落位表）
5 做到了什么（对应哪天判据、什么证据）
6 坑（怎么踩的、下次怎么绕）
```

**第 2 项与第 6 项是这份日志存在的理由**；其余四项只是索引。

---

## 6 文档与代码对账（重构片收尾必跑）

**症状**：文档说 77 个公开项，代码里 104 个；两边都「对」，但没人能判。

**做法**：一个脚本，双向比：

```
代码 pub 符号  → 文档里是否都有声明
文档声明的项    → 代码里是否都存在
输出：=== 对账通过 === 退出码 0
```

**判据：退出码 0 才算对齐。** 靠人读文档判断一致性，等于没有判据。

- [ ] 每片有反套壳判据（删成因，看崩不崩）

- [ ] 每片有开发日志，第 2 项与第 6 项非空
