# 时间与空间：AI 两个盲区的精确表述

> **AI 只写全序，从不校验偏序。**
> **AI 只看见文件，不看见节点在图里的位置。**
>
> 这两行就是「AI 缺时间与空间」的全部内容。本文给出定义、判据、违规形态和落地方法。

---

## 一、为什么单列这一份

**因为测试永远抓不到这两件事，而它们恰好决定了系统能不能用。**

操作者的原话：

> 「任何测试结果都靠不住，而是要真实数据流和信息流的程序，具备时间空间上的认知才可能完成。」

**这句话可以一行证明：**

```
测试  = 在一条确定的执行全序上打点
完成  = 依赖偏序被全覆盖
偏序 有无数条线性扩展，测试只钉住了其中一条
⇒ 测试通过 ⇏ 偏序闭合
```

**不是"测试不好"，是测试的**取值范围**比"完成"小一个维度。**

---

## 二、时间 = 偏序 ⊆ 全序

### 2.1 定义

```
依赖序 ⊑ ：一个偏序。A 必须在 B 之前；X 和 Y 谁先都行。
            （"谁先产生、谁后消费"就是这张偏序图）

执行序 ≤ ：一个全序。代码一行一行跑，任意两步必然有先后。
            （测试、脚本、请求，都是全序）

正确 ⟺ 执行序是依赖序的线性扩展，即 ⊑ ⊆ ≤
违规 ⟺ 存在 (a,b) ∈ ⊑ 但 (b,a) ∈ ≤    ← 名字叫「执行先于依赖」
```

**这段话的出处**（`编程号v1.1` 原样，我只改写了表述）：

```
DG（数据依赖图）：变量 = 节点，赋值 = 边
CT（控制流拓扑）：分支 = 转移，循环 = 环
[数据控制耦合] = {[DG].依赖序 = [CT].执行序} / {[执行先于依赖] + 1}
```

**注意它是等号，不是"都要检查"。**
`依赖序 = 执行序` 是一个**跨算子的等式约束** —— 比两个独立检查强一个量级。

### 2.2 四种违规，逐条对应症状

| 违规形态 | 症状 | 为什么测试抓不到 |
|---|---|---|
| **执行先于依赖** | 用了还没初始化的状态 / 还没建的字段 | 测试里恰好按对的顺序跑，不触发 |
| **依赖边不在任何全序里** | 跨仓库、跨进程、跨浏览器的那条边 | 测试只跑一条全序（单仓库单进程） |
| **偏序有环** | A 等 B，B 等 A，死锁 / 循环依赖 | 单测不会跑到那个组合 |
| **偏序被多条全序同时满足但无互斥** | 数据竞争 | 单测是串行的，天然无竞争 |

**我们那次真实案例属于第二种**：

```
依赖偏序上有边：面板消费后端产出的 401 reason
执行全序里没有：Go 测试只跑后端自己
⇒ go test 全绿，用户仍被踢
```

### 2.3 怎么把依赖序写出来（判据）

**不要求画完整图（那会爆炸）。只要求写「跨界的边」。**

**什么叫跨界**：跨进程 / 跨仓库 / 跨浏览器 / 跨持久化（写盘→下次读）。

**模板（放进 `设计.md` §1.5）：**

```markdown
| # | 产生方（谁先） | 消费方（谁后） | 交什么（字段级） | 跨的是哪个界 | 哪条全序覆盖它 |
|---|---|---|---|---|---|
| 1 | 后端 sessions.go | 面板 client.ts | `reason: idle\|absolute\|ip` | 跨仓库 | `验收.sh --case e2e` |
| 2 | 写入 store | 重启后读 | 整条记录 | 跨持久化 | `验收.sh --case restart` |
| 3 | 服务端换进程 | 浏览器旧连接 | 401 世代号 | 跨进程 | `验收.sh --case restart` |
```

**最后一列是判据**：
**每一条跨界的边，都必须有一条全序覆盖它。写不出 → 这条边现在没人验。**

**⇒ 这一列就是「测试靠不住」的解药：**
不是说不要测试，是说**每条跨界边都得有一条测试专门覆盖它**，而不是指望"整体跑一遍"。

## 三、空间 = 有向图 + 无环

### 3.1 定义

```
位置   ：节点（模块 / 目录 / 文件 / 包）
谁能碰谁：有向边（import / 调用 / 读写）
正确 ⟺ 图是 DAG（无环） 且 边的方向符合分层
```

**出处**（`编程号v1.2` 原样）：

```
MM（模块态射）：模块 = 对象，接口 = 态射
SA（架构拓扑）：分层、依赖方向
[依赖单向]   = {[模块依赖 DAG]} / {[循环依赖] + 1}
[架构正确性] = {[SA].分层清晰 * [SA].依赖方向 * [SA].边界明确} / {[跨层依赖] + [循环架构] + 1}
```

### 3.2 空间盲的两个层次

**第一层：不知道「这类东西放哪」**（归类 / 落位）
→ 已由 `references/placement.md` + `templates/设计.md §2.5 落位表` 解决。

**第二层：不知道「这个位置在图里的坐标」**（架构位置）
→ 本文解决。

**两层的差别：**

| | 第一层（落位） | 第二层（架构位置） |
|---|---|---|
| 问题 | 临时测试接口该放哪 | 这个模块能依赖谁 |
| 判据 | 路径匹配落位表某一行 | 依赖图是 DAG，且方向符合分层 |
| 违规 | 裸放（查不到任何行） | 跨层依赖 / 循环依赖 |
| 工具 | `arch-check.sh` A3 | 需要额外写（见 3.3） |

### 3.3 怎么把空间写出来（判据）

**两张表，都必须有。**

**表 1：模块清单 + 依赖方向**

```markdown
| 模块 | 目录/包前缀 | 能依赖谁 | 绝不能依赖谁 |
|---|---|---|---|
| domain | internal/domain/ | （无） | infra, api |
| infra  | internal/infra/  | domain | api |
| api    | internal/api/    | domain, infra | （无） |
```

**判据**：把它读成一张有向图，**必须是 DAG**。
出现环 ⟹ 这个设计不对，不是代码不对。

**表 2：功能归属**

```markdown
| 功能 | 属于哪个模块 | 为什么 |
|---|---|---|
| 会话校验 | domain | 业务规则，不是传输 |
| 401 响应格式 | api | 传输层契约 |
```

**判据**：新加一个功能，**先查这两张表**。查不到 = 表不全 = **先补表，不许先写代码**。

### 3.4 一种特别隐蔽的空间违规

**「我改的这个文件，是别人系统的输入」** —— 这在本地看不出来。

```
你的仓库 A 改了一个返回格式
  ↓
仓库 B 在解析它（这条边在你本地完全不可见）
  ↓
本地测试全绿，B 崩了
```

**⇒ 判据：凡是改了「对外承诺」（返回值 / 路由 / 字段 / 配置键），
必须去找**这条边上的另一端**。找不到 = 你不知道全图 = 不许改。**

（提取方法见 `references/integration-surface.md` 第三节「接缝提取」。）

## 四、风格 = 必须带数字

**「AI 写代码对风格能力太弱」的解药不是"请写得整洁"，是给数字。**

**操作者那套提示词里，风格全是可测的（原样）：**

```
13. 函数长度无硬性限制，单一职责，超过约 50 行须注释说明职责范围
14. 嵌套深度 ≤ 3，使用早返回或守卫子句
15. 命名遵循语言社区惯例
16. 注释占比 10%~30%，解释"为什么"
17. 语句终止符遵循语言标准
```

**对照"没用的写法"：**

| ❌ 无法执行 | ✅ 可执行 |
|---|---|
| 代码要整洁 | 嵌套深度 ≤ 3 |
| 注释要恰当 | 注释占比 10%–30%，解释"为什么" |
| 命名要清晰 | 遵循 `<语言> 社区惯例`（可查的一份） |
| 函数不要太长 | 超过 50 行必须注释说明职责范围 |

**⇒ 风格契约的三条要求：**

```
F1  必须是数字，或是对可查外部标准的引用（"遵循 X 惯例"）
F2  不许出现"恰当 / 良好 / 合理 / 清晰"这类不可测词
F3  每条都要能被一条命令或一次人眼扫描验出来
```

**模板放进 `设计.md` §2.6。**

## 五、这一份怎么用

**在步 3（设计）里，签收系统设计之后、开程序设计段之前，做三件事：**

```
① 写落位表           → 设计.md §2.5（已有）
② 写依赖序图         → 设计.md §1.5（本文 §2.3 模板）
③ 写模块依赖方向     → 设计.md §2.7（本文 §3.3 表 1）
④ 写风格契约         → 设计.md §2.6（本文 §4）
```

**缺一条 ⟹ `gate.sh` G7 拦，不许写业务代码。**

**然后每一轮螺旋：**

```
改一小块 → 立刻跑覆盖该块「跨界边」的那条全序 → 拿回一条新事实 → 改下一块
```

**不是"整体跑一遍看绿不绿"，是"每条跨界边都有专门的全序覆盖它"。**

---

## 六、一句话

> **测试钉住的是偏序的一条线性扩展。**
> **而系统能不能用，取决于偏序本身有没有闭合。**
>
> **⇒ 把跨界的边写出来，给每条边配一条全序。**
> **这就是「具备时间空间认知」。**

## 七、诚实标注

1. **「依赖序 = 执行序」这个等式来自 `编程号v1.1`**，我保留了它的形式，
   但**在真实代码里严格相等做不到**（并发下执行序不唯一）。实践中用**包含关系**：
   `⊑ ⊆ ≤`，即"执行序是依赖序的一个合法线性扩展"。本文用包含关系，比原文弱一档，更可判。
2. **「每条跨界边配一条全序」成本不低**。一个跨 3 个界、有 12 条边的改动，要 12 条 e2e。
   **本文没有给成本优化方案** —— 只用 `integration-surface.md` 的"先拆高重力接缝"来排优先级。
3. **§5 的四张表是我按判据反推的最小集**，**未在真实项目上完整跑过**。
   跑过之后很可能发现还要加表（比如"事件顺序表"）。
