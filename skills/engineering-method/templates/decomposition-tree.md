# 模板 · P1 分解树

> 用法：拷进项目，先把 `C` 写死，再逐级展开。**每个节点必须填 `criterion`，否则整树不通过。**

## 核心问题

| 字段 | 值 |
|---|---|
| `Question` | （一句话，可回答，禁用"应该/可能"） |
| 冻结时间 | （YYYY-MM-DD HH:MM） |
| git commit | （动手前的 HEAD） |

## 树

| id | question | parent | load_bearing | criterion（命令/断言/证明义务） | evidence_provenance | verdict | close_evidence |
|---|---|---|---|---|---|---|---|
| C | | — | yes | | | | |
| C.1 | | C | yes/no | | | | |
| C.1.1 | | C.1 | yes/no | | | | |
| C.2 | | C | yes/no | | | | |

## 承重汇总（父子一致性检查）

| 父节点 | 承重子节点 | 全部 SUPPORTED? | 父判决是否一致 |
|---|---|---|---|
| C | C.1, C.2 | ☐ | ☐ |

## MECE 自检

- [ ] 同级分支**无重叠**（没有两个分支在回答同一件事）
- [ ] 同级分支**无缺口**（合起来覆盖父问题）
- [ ] 每个叶子都有可执行判据（不是"需要更多数据"）

## 不合格写法举例

| 写法 | 为什么不合格 |
|---|---|
| "分析一下为什么慢" | 不可回答、无判据 |
| "优化数据库" | 把 solution 当 question |
| "这个分支需要更多数据" | 标注证据 ≠ 判定 |
