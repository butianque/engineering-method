# 模板 · 功能片段记录（第 6 段落盘的最小单位）

> **用途**：任何一个功能片段 —— 一个端点、一个字段、一个函数、一条断言 —— 都按这个填。
> **判据**：填不完 = 你自己还有没想清的地方。

---

## 标准格式

```markdown
### <功能名> — <一句话它是什么>

**位置**：`文件#符号名`（用符号，不用裸行号；确需行号时绑 `#token`）

**它干什么**：<一句人话。说「解决什么问题」，不是「做了什么操作」>

**语义**：<术语表编号 + 该术语的一句话定义>

---

#### 数据流

| 项 | 内容 |
|---|---|
| 输入 | <谁产生、什么格式、什么坐标系> |
| 输出 | <ID / 坐标 / 字节> |
| 消费者 | <程序 / 下游服务 / 测试> |
| 失败时 | <观测到什么说明它坏了> |

#### 信息流

| 项 | 内容 |
|---|---|
| 输出 | <读法 / 人话 / 前后文> |
| 消费者 | <AI / 人> |
| **它能推出什么** | <必须写具体结论，见下> |
| 缺失时症状 | <消费者会看到什么假象> |

---

#### 两个消费者

| | AI 能看到 | 用户能看到 |
|---|---|---|
| 正常时 | <逐字段写> | <界面 / 响应> |
| 出错时 | <它知道出错了吗> | <能看到错误原因吗> |
| 被截断时 | <知道丢了多少吗> | <能看到吗> |

---

#### 坏了怎么定位

- **症状**：<观测到什么说明它坏了>
- **判据**：<一条能跑的命令>
- **常见误判**：<曾经以为是 X，实际是 Y>

---

#### 依赖

- 它调用：<符号列表>
- 谁调用它：<符号列表 + `文件:行`>
- 契约前提：<它假设了什么一定成立；谁负责保证>

---

#### 记录

- **这条信息怎么被下一次正确理解**：<文档位置 / 字段注释 / 判据名>
- **首次记录**：<日期 + 谁>
```

---

## 填写纪律

### 「它能推出什么」必须写具体

| 写法 | 判定 |
|---|---|
| 「能理解这个节点」 | ❌ **没写**（等于什么都没说） |
| 「能知道苹果后面是红的」 | ✅ 写了 |
| 「能判断这条记忆可不可靠」 | ❌ 抽象，无法验 |
| 「能看到这条记忆来自哪一轮、哪个工具、什么时候」 | ✅ 写了 |

**判据**：把这句话给一个没读过代码的人看，他能复述出「消费者会得到一个什么结论」吗？

### 「常见误判」不能省

这一栏是**下一个人的捷径**。写法固定：

```
曾经以为是 <X>，实测是 <Y>，因为 <Z>（证据：<文件:行 / 命令输出>）
```

**为什么必须写自己的错**：不是自谦。是**下一个 AI 会重犯同一个错**。

### 「契约前提」要去找违反者

把代码注释里带「前提 / 必须 / 不许 / 只有」的句子抽出来，
**逐条去别的文件找可能违反它的人**。

> 实测教训：某函数的注释写着「前提是检查点与回滚之间没有别的写者」，
> 代码里有两道防线，但**第三处创建实体的路径不在这两道防线里**。
> 缺陷在现场之外。

### 位置用符号，不用裸行号

```markdown
❌ `core/entity.go:244`        ← 函数移到 :413 后，这条指向一行注释
✅ `core/entity.go#computeReadingLocked`
✅ `core/entity.go:413`（`computeReadingLocked`）   ← 允许，但必须带符号名
```

**实测**：某规范文档的 12 条指针里 9 条指错（最大偏移 +135 行）；
某预注册件的 21 条锚点里 15 条失效。原因都是「文件加了上百行，文档没跟上」。

## 极简版（小改动够用）

不是每个改动都值得填全。**极简版至少要有这五行**：

```markdown
### <功能名>
**位置**：`文件#符号`
**干什么**：<一句人话>
**它能推出什么**：<具体>
**坏了怎么定位**：<症状 + 一条命令>
```

**少任何一行 = 这条改动没有记录，下一个人要从零重来。**
