# 任务书（派给子代理的唯一形态）

> **一段都不能省。省哪段，子代理就在哪段自由发挥。**
> **角色先说死**：**你只执行这一份任务；规划与验收归任务发出者。**
> 有问题、有冲突、有做不到的，照实上报 —— 但**不要下「通过 / 完成」这类结论**。
> 依据：`references/r7-slice-board.md` §3–§4。

## 2 先读规范（唯一权威）

## 3 写域

**只许改这些**：

```
<路径>
```

**不许改**：<路径 / 目录 / 别的 crate>。

> 越界即失败，不许「顺手修好」。

---

## 4 冻结契约（签名原样，一个字都不许改）

```
<签名 / struct 字段顺序 / 常量 / 表结构，原样贴出>
```

---

## 5 语义（逐条编号，每条一句，可判）

```
A1 <一句话断言>
A2 <一句话断言>
A3 <边界：空 / 越界 / 不存在 / 重复>
…
```

**判据：每条都能写成一行断言；写不成一行的，是还没想清。**

---

## 6 测试（一个编号一个测试）

```
A1 → tests::a1_xxx
A2 → tests::a2_xxx
```

**禁止**：`#[ignore]`、硬编码期望值、只断言不崩溃。

---

## 7 反证（必须做，必须报告）

```
注入 (a) <改哪一处> ⇒ A__ 必须红
注入 (b) <改哪一处> ⇒ A__ 必须红
注入 (c) <改哪一处> ⇒ A__ 必须红
三处都要「注入 → 红 → 还原 → 全绿」，并报告红在哪条。
```

**没有反证的测试 = 一条永远为真的断言。**

---

## 8 禁止

```
todo! / unimplemented! / #[ignore]
硬编码返回值 / 硬编码期望
吞错误（let _ = / 空 catch）
改冻结契约 / 改 schema / 碰别的写域
```

---

## 9 交付报告必须含

```
1 <命令> 末 20 行（不是「全绿」两个字）
2 实现位置 + 关键 N 行
3 三处注入的红点与还原结果
4 <实际输出>：JSON / 结构体 {:?} / 读回字符串
5 我改了几处 src（0 处也要明说），每处「原写法 → 新写法 → 为什么」
```

**报告里不许下这三句结论**（它们归任务发出者）：

```
✗ 「这一片通过」      ✗ 「测试全绿，可以合了」      ✗ 「验收通过」
```

**要报告的冲突 / 做不到，照实写**（这才是要你上报的东西）：

```
✅ 「任务书 S4 的 3 条与冻结语义的上界 2 条冲突，我按语义做了，请裁决」
✅ 「我够不到 store 的写域，这个洞我复现了但没修」
✅ 「0 处要改」，附结构性理由 + 注入红点
```

---

## 10 机器字段

```
blocked_by: [task-xx]        # 依赖没完成，不许 claim
write_scopes: [路径…]        # 机器可校验的写域
role: execute-only           # 只执行；规划与验收归任务发出者
```

## 自检

- [ ] 六件不可省都在（写域 / 冻结契约 / 语义编号 / 反证 / 报告形态 / 依赖）；段数可按项目增减
- [ ] 语义每条有编号，编号与测试名一一对应
- [ ] 反证 ≥2 处，且写明「哪条必须红」
- [ ] 交付报告五项都在，第 1 项要的是输出，不是结论
- [ ] 已写明「不许自判通过；冲突与做不到如实上报」
- [ ] `blocked_by` / `write_scopes` / `role` 已填
