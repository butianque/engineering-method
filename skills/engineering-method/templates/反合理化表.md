# 反合理化表

> 这份表的用途：**在你准备跳步的那一刻，把理由摊开看。**
> 补充模板见 `../references/05-excuse-table.md`。

---

## 一、铁律（四条）

```
I1  没有集成面表，不许开始写业务代码。
I2  集成面表里还有「不存在」，不许声称完成。
I3  验收脚本没跑过（退出码 0），不许声称完成。
I4  探针红了，不许自己改探针 —— 先交给另一个 AI 问，拿回依据再改。
```

---

## 二、借口 → 现实

| 借口 | 现实 |
|---|---|
| 「这个改动很简单，不用立项」 | 简单的是你看到的那一块；缺的是你没看到的其余六块 |
| 「测试都过了」 | 测试只能断言**已写代码**的行为。不存在的东西不产生红色 |
| 「我在脑子里过了一遍」 | 脑内过一遍没有退出码 |
| 「集成面表我列了，都是"存在"」 | 先跑 `gate.sh`。行数、探针、状态，机器说了算 |
| 「探针红了，肯定是探针写错了」 | I4：先问 AI2，拿回依据（文件:行号 / 命令输出）再改 |
| 「AI2 说没问题」 | 依据呢？没有 `文件:行号` 或命令输出 = 无效回答 |
| 「先做完再补表」 | 补的表一定是照着代码写的，等于把现状当应有 |
| 「这行写不出探针，先标"存在"吧」 | 写不出探针 = 无法证明存在 = 按 `不存在` 算 |
| 「另一个仓库不用改」 | 你验证过另一个仓库的调用点吗？没验就是不知道 |
| 「用户没说要这个」 | 用户说的是他的困境，不是他要的零件。第 4 行（数据）是困境的一部分 |
| 「这次赶时间」 | 赶时间时省掉的正是"看不见的那部分"，事后返工一定更久 |
| 「之前都是这么做的」 | 之前也一直在"零散" |

---

## 三、Red Flags（看到自己在说这些，立刻停）

- 「应该」「可能」「大概」「通常」「我记得」
- 「我看了一下，没问题」
- 「这里逻辑上是通的」
- 任何形式的「先这样，后面再补」

**处置**：停下，去跑一条命令。**跑不出命令，就写 `不存在`。**

---

## 四、违规后的处置（不是"下次注意"）

| 违规 | 处置 |
|---|---|
| 没立项就写业务代码 | 代码**不算数**，先补表，再重做 |
| 表里有"不存在"却声称完成 | 该次"完成"**作废**，回去做那几行 |
| 验收没跑就报"好了" | 该声明**作废**，跑完再报 |
| 自己改了探针让它变绿 | 该轮**作废**，问过 AI2 再来 |
| 判据在结果出来后才定义 | 判据被视为**已污染**，作废 |

---

## 五、被追问时的标准回答

| 被问 | 答 |
|---|---|
| 做完了吗 | 「集成面 N 行：存在 M、新建 K、不存在 0；验收退出码 0。日志在 `.runs/`」 |
| 有什么风险 | 指向证据等级里标 `assumption` 的那几条 |
| 怎么证明 | 给命令 + 输出，不给描述 |
| 还缺什么 | 指向集成面表里状态为 `不存在` 的行（若为 0，答"按 7 行骨架无缺口，骨架外未覆盖"） |

**注意最后一句的诚实度**：7 行骨架之外还有未覆盖的（比如"连错都不知道"的那类）。
**不许说"全都没有问题"。**
