# 文档宪法（改法 / 编号 / 唯一权威）

> **这一份只说两件事**：文档怎么改（§1）、编号怎么分（§2）。外加一张「谁说了算」的表（§3）。
> **违反本文件的文档，按「未完成」处理，不进判据。**
>
> 依据：`references/r6-project-charter.md` §3。

---

## §1 六条硬规

### D1 · 只写当前真相，不写补丁

```
禁止：修订记录、补记、追加说明、「原写…现改为…」、变更日志段落、日期标注
要求：把旧句子直接替换成新句子；读者看到的永远是唯一一份当前说法
```

**为什么**：补丁式文档让同一份文件里并存两套说法，读者无法判断哪句生效。历史留在 git，不留在正文。

### D2 · 插入 / 替换 / 删除，三选一

| 动作 | 什么时候用 |
|---|---|
| **插入** | 缺一节；插到它应在的位置，不改别的节号 |
| **替换** | 改一段说法：整段换掉，不留「原文如下」 |
| **删除** | 说法作废或已被别处覆盖：整节删掉，同时把引用它的地方改指新位置 |

**禁止**：追加到文件末尾当「补充说明」。

### D3 · 一个概念只有一处

同一件事（写路径、触发条件、表结构、装配顺序、判据编号）**只在一份文件里定义**，其余只引用。

**判据**：`grep` 该概念的定义句，全仓命中 **1 处**。

### D4 · 文件数只减不增

新增一份文档必须有**它独占的概念**；否则并进已有文件。
目标：每域一到两份 + 一份宪法 + 一份状态表。

### D5 · 编号不复用、不递增

前缀一经分配（§2）永不给别的域；同域内编号连续，删除后**留空**，不给后来者补位。

### D6 · 完成后改状态，不重读

任务完成时只改状态表的一行 + 证据指针。
**任何 agent 接手前先读状态表**；状态为「定稿」的，不再读其正文。

## §4 可 grep 的纪律判据（NR1–NR9）

```
NR1 不存在裸写的旧编号（A1 / E1 / G1 / L1 / M1 / U1 / V1 / I1 / D1 / H1）
NR2 每个前缀只出现在一个文件
NR3 每个概念的定义句全仓 1 处
NR4 写路径只在数据流文档定义；读路径只在它自己那节定义
NR5 不变量只在范畴表定义
NR6 判据汇总只引用，不新造编号
NR7 正文不含修订 / 补记 / 追加 / 「原写…现改为」类补丁段
NR8 文件数不增长（新增须先删旧的或证明独占）
NR9 完成状态只在状态表改一行
```

**⇒ 写不成脚本的纪律，等于没有纪律。**

## §5 串 / 并 / 汇（一处改了，谁必须跟着改）

```
【串】设计链
  范畴（词 / 不变量 / 语言）
      → 架构（层 / 位置 / 层间接点）
      → 工程架构（包 / 接缝 / 选型）
      → 框架（模块 / 装配顺序）
      → 细则（写法）

【并】两条独立线
  形式化证明（证范畴与数据流的命题）  ∥  数据流 / API（步骤 / 表 / 端点）

【汇】依赖上面全部
  消费者（回路 / 端到端）依赖 API
  判据（形式化 / 单元 / 端到端 / 结构 / 数字 / 未验证 / 红线）依赖全部
```

**规则：串链每一环只依赖它前面那环，不反向依赖。**
