# 立项书（基准 / 域的推导）

> **它回答的不是「要做什么」，是「要让这件事成立，必须存在哪几类东西」。**
>
> 一页纸的顺序不许换：**困境 → 推域 → 划界 → 引导记录 → 兜底 → 不做 → 落实**。
> 允许写「不知道」，**不许留空**——留空是最坏的一种谎。
>
> 依据：`references/r6-project-charter.md`（五步推导 / 三件套 / 六种问法 / 判据）。

## §2 推域（一行一个域；数量由问题决定，不由模板决定）

**推法**：要让 §1 的困境消失，必须同时存在哪几类东西？每答出一条，加一行。

| # | 域（范畴） | 管什么（每个词一句定义 + 一个反例） | 不管什么（边界） | 删掉它会怎么坏 | 入口文档 |
|---:|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |

**三条硬判据**：

```
1 每一格非空（写「不知道」也算非空，空格不算）
2 「删掉它会怎么坏」说不出 ⇒ 它不是域，并进别的域
3 入口文档必须是真实存在的路径；没有就现在建，不许写「待建」
```

**三个必须被问过的问题**（答案可以是「本版不做」，但不许没问）：

- [ ] **词与边界**：核心词各自指什么？什么不算它？
- [ ] **消费者**：谁在什么时机用？失败时谁受影响？
- [ ] **判据**：怎么算过？红哪一条不许合？

> 这三条是**问题**，不是「必须有的三个域」。它们可能各自成域，也可能落进别的域。

## §3 域之间的关系

```
串：A 的输出是 B 的输入（B 不许反过来依赖 A）
并：A 与 B 互不依赖，可同时做
汇：X 依赖上面全部（常见：消费者、判据）
```

| 关系 | 涉及哪些域 | 说明 |
|---|---|---|
| 串 | | |
| 并 | | |
| 汇 | | |

**规则：串链每一环只依赖它前面那环。反向依赖 = 环形 = 谁也改不了。**

## §6 未知项（≥1 条）

|---:|---|---|---|
| 1 | | | |

> 写「不知道 X，打算用 Y 验」是合法状态。留空说明「我以为我都知道了」——那通常是盲区所在。

## §7 落实（不打补丁）

```
D1 只写当前真相：禁止「原写…现改为…」「补记」「修订记录」
D2 插入 / 替换 / 删除，三选一：禁止追加到末尾当补充
D3 一个概念只有一处：其余只引用，不复述
D4 文件数只减不增：新增须有独占概念
D5 编号不复用、不递增：删除留空
D6 完成改状态不重读：只改 §8 一行 + 证据指针
```

**现状**：本项目的落实纪律写在 `<路径>`；若只有本文，就把上六条当作纪律。
