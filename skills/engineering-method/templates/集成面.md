# 集成面表

> **这是整个 skill 的核心。** 它不解决"这个功能对不对"，它解决"这条链路缺了什么"。
>
> **行数固定。** 7 行骨架不许删；按改动类型追加行；只增不改。
> 原因：如果行可以由 AI 自由增删，它会把自己没想到的那一行直接删掉，报告就全绿了。

---

## 状态列只有三个值

| 值 | 含义 |
|---|---|
| `存在` | 已经有，探针能验到 |
| `本次新建` | 这次要新建的 |
| `不存在` | **该有但没有** ← 这一行就是待做清单 |

**写不出探针的行，一律标 `不存在`。**
**写不出探针 = 现在无法证明它存在 = 按不存在算。**

## 一、7 行骨架（不许删）

| # | 要素 | 探针（一条命令，5 秒内，返回 0=存在 / 非0=不存在） | 状态 |
|---|---|---|---|
| 1 | 入口（路由 / CLI / 事件） | | |
| 2 | 业务函数本身 | | |
| 3 | 谁调用它（接线） | | |
| 4 | 数据从哪来 / 存哪里 | | |
| 5 | 失败路径（错误怎么传） | | |
| 6 | 配置 / 权限 / 并发 | | |
| 7 | 可观测 / 可回滚 | | |

**这 7 行是什么**：一条真实链路上**必须同时成立**的 7 件事。
AI 通常只做第 2 行，然后报告"功能已实现"。

## 三、探针怎么写（三种模板）

### ① grep 型（结构存在性）

```bash
grep -rq "EnsureSequence\|INSERT INTO" internal/store/ && exit 0 || exit 1
```

### ② 命令型（能跑通）

```bash
curl -sf -o /dev/null http://localhost:8080/health && exit 0 || exit 1
```

### ③ 断言型（行为正确）

```bash
[ "$(curl -s -o /dev/null -w '%{http_code}' -X POST http://localhost:8080/api/x -d '{}')" = "400" ]
```

**三条纪律：**

```
P1  必须是命令，不是"人工判断"
P2  必须 5 秒内跑完
P3  必须只读 —— 探针不许改数据
```

## 四、跑 gate

```bash
bash ../scripts/gate.sh .          # 判能不能开始写代码
bash ../scripts/gate.sh . --done   # 判能不能声称完成
```

**它会验**：7 行骨架齐不齐 → 有没有"不存在" → 探针是不是空的。

## 五、悬置审计（进阶，可选）

**想知道某一行是不是真的必需：假设它不存在，跑链路，看断不断。**

| 结果 | 判决 |
|---|---|
| 断（编译失败 / 500 / 超时 / 数据丢失） | **承重** —— 保留，且优先级最高 |
| 不断 | **装饰** —— 降级为可选 |
| 拿掉之后反而更好 | **干扰** —— 删掉 |

**这比"我觉得需要"强的地方**：它有退出码。

**优先拆哪个**：越是被多处依赖的越先拆（约束密度高 = 承重墙）。
